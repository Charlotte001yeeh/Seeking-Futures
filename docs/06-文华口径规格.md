## 0. 推翻与修正摘要

| # | v1 总设计的假设 | 官方实际规则 | 影响 |
| --- | --- | --- | --- |
| 1 | 主力 = **持仓量最大**，次主力超 **1.1 倍** 才换月 | 主力 = **成交量与持仓量双料最大**；不满足时**维持原主力**；仅当旧主力两项都不是第一才让位给成交量最大者。**无任何倍数阈值** | 判定算法**完全重写** |

## 1. 主力合约判定（官方规则帖原文）

### 1.1 四条成文规则

| # | 原文要点 |
| --- | --- |
| 1 | 每个品种只选出**唯一一个**主力合约 |
| 2 | **日成交量和持仓量都为最大**的合约 → 新主力，**下一交易日**切换指向 |
| 3 | 未满足第 2 条前，维持原主力不变 |
| 4 | 若当前主力的成交量与持仓量**都不是最大** → 下一交易日让位，新主力指向**成交量最大**的合约 |

### 1.2 三个关键否定

- ❌ **没有倍数阈值**（不是"次主力超主力 N 倍"）
- ❌ **没有"次主力"概念** —— 官方原文："次主力是其他软件中的概念……文华中是采用更严格的持仓量和成交量双重标准，每个品种只有一个主力。就没有查看次主力的必要了"
- ❌ **盘中不切换** —— 官方 FAQ："主力合约切换是在**盘后**进行……如果盘中满足，盘中不会立即切换，等到收盘的时候如果依然满足成交量和持仓量最大，那么盘后会进行切换"

### 1.3 实证案例（客服逐日核对）

郑煤换月争议中，客服给出的判断依据是：
> "郑煤1809昨日成交量229454，1901昨日成交量212362，所以今日不发生换月"

→ 确认**以昨结算后的日度数据为准**，且**成交量是可比判据**。

### 1.4 我们的实测验证

**方法**：拉取上期所 2026-09-08 ~ 09-15 共 6 个交易日日报，对全品种按 §1.1 状态机逐日推演。

| 检验项 | 结果 |
| --- | --- |
| 触发换月次数 | **0** |
| "当前主力 == 双料最大" | 101 天 |
| "当前主力 ≠ 双料最大" | **29 天（规则 3 全部正确维持）** |
| 上期所「量最大 ≠ 仓最大」的品种 | **7/25**（al、zn、au、ag、ss、bu、br） |

**结论：规则自洽且可复现。** 那 29 天正是换月过渡期，规则 3 的"维持"设计避免了在过渡期反复横跳。

**沥青实例**（2026-09-15）：

```
bu2611   成交量 296,894 (#2)   持仓量 255,342 (#1)   ← 仓最大
bu2610   成交量 710,945 (#1)   持仓量 156,698 (#2)   ← 量最大
→ 无 dual → 维持原主力 bu2611
```

**过渡期的业务含义**：近月成交量领先（投机资金仍在），远月持仓量领先（产业资金已移仓）。文华的"维持"策略在过渡期是保守且稳定的。

### 1.5 与东方财富口径的差异（必须记录）

| | 文华 | 东方财富 |
| --- | --- | --- |
| 判定 | 量+仓**双料最大**，否则维持 | **成交量最大** |
| 方向 | 可进可守 | **只向前，不回退** |
| 时点 | 盘后确认、次日生效 | 每日收盘结算后 |

→ 实测 09-16 东财为沥青选的是 `bu2610`（量最大），文华口径下应是 `bu2611`（仓最大）。**用东财主力标记去对齐文华，在过渡期必然失真。**

## 2. 主连 / 加权 / 指数

### 2.1 主连（官方说明书原文，WT8）

> "主连 k 线图数据，由各个月份合约的数据拼接形成。把每一个月份合约**主力期间以前的 k 线图砍掉**，再把**主力期间以后的 k 线数据砍掉**，剩下主力期间的部分 k 线图，然后按照时间顺序拼接在一起……这种掐头去尾的处理机制破坏了 k 线趋势的连续性和完整性，**造成主力月份切换时有很大的价格跳空，造成了趋势的失真**……**不适合直接用于策略回测计算的**。"

- **无前复权 / 无后复权**（三款客户端均无该选项）。
- WT9 的对策是"**主连链回测**"（用各月份合约自身 K 线算信号 + `Trade_Chain` 机制）—— 这是**回测口径修正，不是价格复权**。
- 换月当天模组"默认平旧主力、开新主力"，**不支持修改**。

### 2.2 加权 / 指数 / 次主连

| 概念 | 定义 |
| --- | --- |
| **加权** | 各月份合约价格按**持仓量加权平均**：`Σ(最新价×持仓量) / Σ持仓量`，映射主力月份走势，**无跳空** |
| **指数** | 各月份合约按持仓量加权，反映品种整体，曲线更平滑 |
| **次主连** | **文华不提供**（无次主力概念） |

### 2.3 传闻澄清

社区有文章称"文华 888 为复权主连"。该说法**来自第三方博客，与文华官方说明书"完全不复权"直接冲突，判定为不可采信**。
→ 本项目**不引入**平滑主连作为"文华口径"；若要平滑序列，作为**本项目自有增值字段**并明确标注 `adjusted=true`。

## 3. 20 日涨跌幅（D1 的核心指标）

> **状态：✅ 已定标完成（2026-09-16，33/33 精确命中）**
> 完整验证记录与最终榜单见 `09-20日涨跌幅rank20完整版.md`；实现规范见 `04 §3.5.5`。

### 3.0 最终结论（先看这里）

```
20日涨跌幅 = (今日收盘价 − 基准日结算价) / 基准日结算价 × 100
基准日 = T−20（2026-09-16 时为 08-19）
```

| # | 规则 |
| --- | --- |
| R1 | 分子 = **今日收盘价**（盘中=最新价） |
| R2 | 分母 = **基准日（T−20）结算价** |
| R3 | **例外**：该合约 T−20 无成交 → 基准前移到最近有成交日（菜籽、胶合板 → 08-18） |
| R4 | 主力合约由 **T−1 日**数据判定（T−1 量最大） |
| R5 | **跨换月不拼接**，用当前主力合约自身序列 |
| R6 | 包含 DCE **月均价期货**（`F` 后缀） |
| R7 | 商品与金融期货**混合排名** |

### 3.1 公式

文华官方公式函数表中，`REF(X,N)` = "引用 X 在 N 周期前的值"（官方例：`REF(CLOSE,5)` 取当前周期前 5 个周期的收盘价）。

```
20日涨跌幅 = (C − REF(C,20)) / REF(C,20) × 100
```

**注意**：这个数学式本身是对的，但**不能直接套用**——`REF(C,20)` 里的"20 根 K 线"对**低流动性合约**会因序列缺日而取错基准。
正确实现必须**按交易日历固定锚定 T−20 日期**，再取该合约当日的结算价。

### 3.2 早期探索的候选口径（均已废弃，留作记录）

| 候选 | 口径 | 实测结论 |
| --- | --- | --- |
| **A** | 主连·收盘·REF20 | ❌ 与文华偏差达 −2.56（sc）/+1.55（rb）/−0.26（cu） |
| **B** | 主连·结算·REF20 | ❌ |
| **C/D** | 主连·收盘·REF19 / REF21 | ❌ |
| **按 K 线条数倒数第 20/21 条** | 用合约自身序列条数计数 | ❌ 各合约序列长度不一，锚点被带偏（碳酸锂曾算成 −18.39%，正确值 −16.97%） |

**唯一正确**：固定锚定 T−20 日期 + 取该日结算价 + 同合约不拼接。

### 3.4 配置项

```yaml
pct:
  pct20:
    method: same_contract      # 同合约（不拼接）
    base_offset: 20            # T-20
    base_price: settle         # 基准取结算价
    quote_price: close         # 今日取收盘价
    zero_volume_fallback: true # T-20 无成交则前移
  main_contract:
    rule: t_minus_1            # 用 T-1 日数据判定主力
    criterion: volume_max

```yaml
pct:
  basis_daily: prev_settle      # 当日涨跌幅基准：prev_settle | prev_close（按交易所可覆盖）
  method_20d: main_continuous    # 20日口径：main_continuous(主连) | same_contract(同合约)
  price_20d: close               # 取价：close | settle
  periods_20d: 20                # 周期数：20（交易日）
```

### 3.5 复现时的注意事项

| 注意点 | 说明 |
| --- | --- |
| **换月跳空** | 未复权主连在换月日有跳空（文华官方承认），故跨换月品种的 20 日涨跌幅是**名义值**，须输出 `rolled_over` 标记 |
| **周期语义** | 确认"20 日"= 20 个交易日（推荐）还是自然日近似 |
| **涨跌幅基准** | 同日涨跌幅一样，取决于 wh6 个性化设置（昨收盘/昨结算） |
| **夜盘** | 文华"夜盘不计算白盘合约"，需与 20 日窗口的日界对齐 |

## 5. 数据来源与"自有计算"字段

### 5.1 来源：与交易所同源

文华持有：中金所、上期所、**大商所（深度行情/L2，许可证号 2026L2-01，有效期至 2026-12-31）**、郑商所（五档行情）、广期所、上金所、上交所、深交所、北交所，以及 CME/ICE/LME/HKEX/SGX/Eurex/OSE/Nasdaq 行情经营许可。

上期所 2025 年度授权行情服务机构名录将**上海文华财经资讯股份有限公司列为"实时行情服务商"**（上期能源同列）。

### 5.2 字段归属（决定性：官方 API 结构直接暴露了分界）

```cpp
// 文华官方历史数据 API 的 K 线结构（来自官网文档）
struct CWHKLineData { int Time; float Open, Close, High, Low, Volume, OpI;
                      float AVPrice;  // 均价
                      float Scale;    // 主动买卖比例
};
struct CWHTickData  { int Time; float Price, Volume, OpI; int Activity;  // 0主动买/1主动卖/2其他
                      float AVPrice; float fBid[5], fBidVol[5], fAsk[5], fAskVol[5]; };
```

| 字段 | 归属 | 本项目 |
| --- | --- | --- |
| OHLC / Volume / OpI / 五档 | **交易所原始** | ✅ 可取，天然一致 |
| 结算价 / 涨跌 | **交易所原始** | ✅ 可取（SHFE `SETTLEMENTPRICE`、CZCE `今结算`） |
| **AVPrice 均价** | **文华自有计算** | ❌ 不复现 |
| **Scale 主动买卖比例** | **文华自有计算** | ❌ 不复现 |
| **Activity 主动买/卖归因** | **文华自有计算**（注：两份官方文档对 `Activity=2` 的措辞不一致——C++ 写"其他"、Python 写"半买半卖"，**口径本身在文华内部都不统一**） | ❌ 不复现 |
| **资金流 / 沉淀资金 / 波段高低点** | 客服："那是**后台计算的，不支持导出**" | ❌ 无公式公开 |
| **指数标尺化** | 客服："标尺化可以看做是赋予权重的过程，**具体的计算方法，涉及内部机密，不便透露**" | ❌ 算法不公开 |

> **结论**：本项目**不使用替代值伪造**这些字段。前端明确显示"该字段文华有、本项目无"。若确实需要，唯一官方路径是 **WT9 付费 API**。

### 明确区分

- **官方支持**：wh7 付费导出、WT9 付费 API、模组导出。
- **第三方逆向**：直接读取软件缓存 `.dat`、内存挂钩、模拟客户端协议 → **本项目一律不做**。

## 7. 合规边界

### 7.1 许可文本

- **文华侧**：大商所许可载明用途为"**通过互联网传输，用户使用终端软件接收**"，范围全球。→ 授权链条**终点是"终端软件接收"**，不含再分发权。
- **交易所侧**：上期所/上期能源名录页明文"**任何未经授权的单位和个人不得擅自转发或传播……行情信息，否则将承担相应的法律责任**"。

### 7.2 场景判定

| 场景 | 判定 |
| --- | --- |
| 自己终端看数据，本地系统读**自己合法取得的数据**，仅自己用 | ✅ 合规 |
| 同一**局域网内**给同事做内部看板，不收费、不外传、不公开 | ⚠️ **灰色但风险较低**（字面上仍属"转发/传播"，但无商业获利、无公开传播） |
| 看板/接口**开放给外部、客户、付费用户**，或公网展示 | ❌ **明确违规**（交易所 + 文华双重授权问题） |
| 逆向读取 wh6 本地缓存来取数 | ❌ 违反软件许可，风险更高 |
| 自己**从交易所采购授权**后自建链路 | ✅ **最干净**，且能真正保证同源可信 |

### 7.3 本项目的定位与红线

- 定位：**个人 / 局域网内部自用研究看板**。
