# 独立性验收：整个项目不依赖任何 DSH 插件

> 结论：**产品（每日日报 + 实时后端 + 局域网前端）只依赖 Node 内置模块，零第三方包、零 DSH 插件。**
> DSH 插件 `dsh-rank20-daemon` 在本项目里是**可选适配壳**：删掉它，产品照跑。
>
> 可执行证明：`node standalone/test/verify-independence.mjs` → **20/20 通过**
> （产品入口依赖闭包 **28 个文件 / 第三方依赖 0 个**）。

---

## 1. 一个目录，两个角色

`rank20-daemon/` 同时承担两件事，必须分清楚，否则"依赖"会被看混：

| 路径 | 角色 | 外部依赖 | 谁在用 |
| --- | --- | --- | --- |
| `rank20-daemon/dist/**`（除 `index.*`） | **纯产品库**：六所抓取器、20 日口径、基准表、日K合成、命名 | **零**（只有 `node:*` + 同目录相对 import） | `standalone/`、`realtime-server/` 直接 import |
| `rank20-daemon/dist/index.js`、`dist/types/index.d.ts` | tsc 产出的**适配壳**（唯一 import `schemastery` 的地方） | `schemastery`、`cordis`（类型） | 只有 DSH 宿主 |
| `rank20-daemon/lib/index.js` | esbuild 单文件**宿主入口** | `schemastery`、`cordis`（external） | 只有 DSH 宿主 |
| `rank20-daemon/src/index.ts` | 适配壳源码（定时器 / 幂等 / 生命周期） | `schemastery`、`cordis`（类型） | 只有 DSH 宿主 |
| `rank20-daemon/cordis.patch.yml` | bundle patch（把插件挂进 profile 配置树） | — | 只有 DSH 宿主 |

**产品运行时的 import 里没有 `index.*` / `lib/`**，也没有 `schemastery`。
`rank20-daemon/dist/naming.js` 里那句 "插件外壳（index.ts）import 了 schemastery，独立脚本不能依赖它" 就是这条边界的注释。

## 2. 验收方法：传递闭包（不是肉眼扫描）

```bash
node standalone/test/verify-independence.mjs
```

做法：从三个产品入口出发，沿相对 import 一路走到底，闭包里**只允许 `node:` 内置模块**。

```
入口 = standalone/start.mjs
     + standalone/daily-job.mjs
     + realtime-server/src/index.mjs
```

| # | 断言 | 实测 |
| --- | --- | --- |
| A1 | 闭包完整解析，无悬空相对引用 | 28 个文件 |
| A2 | **闭包内零第三方/裸包** | 0 个 |
| A3 | 闭包含算法/采集库 | `rank20-daemon/dist` 7 个 |
| A4 | 闭包含实时服务 | ✓ |
| A5 | 闭包**不含**任何 DSH 适配壳文件 | ✓ |
| B1 | 产品目录（39 个文件，已排除测试）零第三方 import | ✓ |
| B2 | `rank20-daemon/dist` 纯产品部分零外部依赖（17 个文件） | ✓ |
| B3 | 适配壳外部依赖清单 = 仅 `cordis` / `schemastery` | ✓ |
| B4 | 产品运行时**零引用**适配壳 / DSH 包 / `schemastery`（去注释后判定） | ✓ |
| B5 | 适配壳可整体删除（dist 不反向依赖它） | ✓ |
| C1 | 产品代码不引用 `DSH_HOME` / `~/.dsh` / 注入器 | ✓ |
| D1 | 前端 `fetch` 目标全为同源相对路径（8 个） | ✓ |
| D2 | HTML 只引用本地 `app.js` / `style.css` | ✓ |
| E1–E3 | `standalone` / `realtime-server` 无 `dependencies` | ✓ |

为什么用闭包而不是关键字扫描：**间接引入也能抓住**。任何一层（例如某天在 `kline.mjs` 里顺手 `import z from 'schemastery'`）都会让 A2 立刻变红。
另外判定前先**去注释**：文件里"提到" `schemastery`（例如说明为什么不能用）不算依赖 —— 否则会把注释当依赖，误报。

## 3. 每日 09:00 的日报只由一个组件负责

**实测发现的双跑（2026-09-23 体检）**：两个组件都在 09:00:00 被唤醒，各自完整抓了一遍六所 32 天数据：

| 承担者 | 当天用时 | 结果 |
| --- | --- | --- |
| DSH 插件 `dsh-rank20-daemon` | 144.2s | 交易日 20260922 / 基准日 20260825 / 品种 84 |
| 独立调度器 `standalone/scheduler.mjs` | 165.4s | 同上（同分同秒写盘） |

两边合计约 **5.5 万行**，并**并发写同一批文件**（`base.json` / `盘中实时.md` / `kline/`）。
幂等判据本身存在（"今天是否已产出 `base.json`"），但两边都在 09:00:00 检查、都发生在对方写盘之前 —— **竞态，幂等挡不住**。

**决定（用户裁定）：日报只由独立调度器负责。**
落地方式与既有的 `rtEnabled: false` 完全对称 —— 一件事只让一个组件做：

```yaml
# rank20-daemon/cordis.patch.yml
dailyEnabled: false        # 每日日报交给 standalone/scheduler.mjs
hour: 9
rtEnabled: false           # 实时轮询交给 realtime-server
```

- `dailyEnabled === false` 时插件**既不定时也不再启动补跑**，日志明确写：
  `⏸ 每日日报已关闭（dailyEnabled=false）—— 由独立调度器 standalone/scheduler.mjs 负责`
- 默认值仍是 `true`（插件单独使用时自洽）；判定用 `=== false` 而不是真值判断，
  这样"没传这个键"（宿主未填默认值 / 裸调用 / 测试）等价于**开启**，不会误关。
- 验收：`rank20-daemon/test/lifecycle.test.mjs` → **31/31**，其中 T8 专门覆盖
  「`dailyEnabled:false` 不 arm 定时器、不抓取」与「不传时默认开启」。

## 4. 想让 DSH 彻底不参与

产品不依赖插件，所以下面两条都可行：

```bash
# A) 保留插件但不让它做任何事（当前状态：日报/实时都已移交）
#    见 rank20-daemon/cordis.patch.yml 的 dailyEnabled / rtEnabled

# B) 彻底卸载（产品不受影响；随时可再装回）
dsh plugin --profile web remove dsh-rank20-daemon
dsh --profile web --dump-config      # 验证组合
```

只跑产品（完全不启动 DSH）：

```bash
node standalone/start.mjs            # 调度器（每日 09:00 日报）+ 实时服务 + 前端
```

## 5. 尚未解决（如实记录）

- **运行中的 DSH 进程仍持有旧配置**（该进程启动时 `dailyEnabled` 这个键还不存在）。
  在 DSH 重启之前，插件那颗 09:00 的定时器仍然有效 —— 也就是说**明天 09:00 若不重启 DSH，
  仍会双跑一次**。重启 DSH 后配置立即生效，此后只有独立调度器跑日报。
  - 已试过 `dev_reload_package dsh-rank20-daemon`（重建 fiber）：**不够** ——
    重载用的是内存里的 loader 条目配置，日志仍打印 `⏰ 下次运行：2026/9/24 09:00:00`。
    配置只有在 DSH **重启（重新组合）**时才重新读取；组合结果已用
    `dsh --profile web --dump-config` 验证：`dailyEnabled: false`，无重复 entry。
- **构建工具链**已改为**不依赖 DSH**：`build.mjs` 先找本仓库自带的
  `node_modules/typescript` 与 esbuild，DSH checkout 只作开发机兜底；
  也可用 `TSC_JS` / `ESBUILD`（或旧的 `DSH_TSC_JS` / `DSH_ESBUILD`）显式指定。
  一只装了 `typescript` + `esbuild` 的机器即可构建，无需 DSH。
