## 1. 抽离敏感参数

### 问题

大商所（DCE）官方 API 的 `apikey` + `secret` **硬编码在源码里**，并且编译进了三处产物：

```
rank20-daemon/src/types.ts                 ← 源头
rank20-daemon/dist/types.js                ← tsc 产物
rank20-daemon/dist/types/types.d.ts        ← 类型声明
rank20-daemon/lib/index.js                 ← esbuild 单文件产物
```

一旦 `git push`，凭据就进了公开历史 —— 而且**改一行再提交并不能补救**（历史里还在，需要 rewrite history + 轮换凭据）。

### 做法

| 步骤 | 内容 |
| --- | --- |
| ① 新增 `rank20-daemon/src/env.ts` | 零依赖的环境读取：`.env` 解析（注释/引号/行内注释）、`env(name, fallback)`、`dceCredentials()` |
| ② 删掉源码常量 | `types.ts` 里改为 `export { dceCredentials, DCE_DEFAULT_HOST } from './env.js'` |
| ③ 调用点改为按需取用 | `exchanges.ts` 的 `dceLogin()` / `fetchDce()` 在**调用时**取凭据，不在模块加载期 |
| ④ 仓库模板 | `.env.example`（值为空占位）+ `.gitignore` 忽略 `.env` |
| ⑤ 本机凭据 | 写入 `.env`（被忽略，仅本机使用） |
| ⑥ 重新构建 | `npm install && node rank20-daemon/build.mjs` → 产物里不再有明文 |
| ⑦ 回归守卫 | `rank20-daemon/test/env.test.mjs`（15 项）+ `tools/audit-publish.mjs` 的 A1 扫描 |

### ⚠️ 必须做的一件事：轮换旧凭据

旧值曾以明文存在于源码（以及被 DSH 注入器加载过的 `lib/index.js`）。
**即使这些文件从未被 push，也建议到大商所官网重新生成 API 凭据**，然后替换 `.env` 里的两行。
（本仓库此前**不是** git 仓库，`git log` 里没有旧值，所以不存在"历史泄漏"问题。）

### 缺凭据时的行为（刻意"响"而不是"静默降级"）

`dceCredentials()` 抛出的错误会明确告诉使用者缺哪个变量、去哪申请、`.env` 怎么写：

```
未配置大商所（DCE）官方 API 凭据：缺少 DCE_API_KEY / DCE_SECRET。
  · 官网免费注册后获取：https://www.dce.com.cn/ → 数据 → API 服务
  · 然后在仓库根目录建 .env（可从 .env.example 复制）：
        DCE_API_KEY=你的apikey
        DCE_SECRET=你的secret
  · 或直接设置同名环境变量（CI/容器里推荐）
```

原因：六所数据缺一会让"当日是否完整"的校验不通过，整轮退回上一完整交易日；
静默降级会让人以为榜单是当天的。

## 2. 不入库清单（及理由）

| 路径 | 理由 |
| --- | --- |
| `.env` | 真实凭据 |
| `rank20/` | **运行时数据产物**：日报 md/csv、`base.json`、`kline/`、`盘中实时.*`。随日期增长；首次运行自动生成 |
| `realtime-server/var/`、`*/var-*/` | 日志、状态文件、`model.json`（模型 Key）、落库 JSONL |
| `node_modules/`、`package-lock.json`？ | 依赖目录不入库；**lock 文件入库**（保证可复现安装） |
| `super-injector-src/` | 从发布 sourcemap 还原的 **DSH 注入器源码**：版权属原发布方，且属于宿主工具、非本项目组件 → **不再分发** |
| `docs/*.docx` | 交易所官方接口文档（© 交易所）→ 请到各自官网下载，不随仓库分发 |
| `rank20-daemon/rt-cadence-*.json|.md` | 实时节拍探测的一次性产物（已删除；脚本迁到 `tools/probes/`，产物写到 `tools/probes/out/`） |
| `rank20-daemon/rank20/` | 测试用 `outDir` 默认值跑出来的残留数据目录（已删除） |

### 例外：故意入库的生成产物

| 路径 | 为什么入库 |
| --- | --- |
| `rank20-daemon/dist/**` | **运行时库**：`standalone/` 与 `realtime-server/` 直接 `import` 它。入库后 clone 下来**无需构建**即可跑 |
| `package-lock.json` | 固定构建工具链版本，保证 `npm ci` 可复现 |

`rank20-daemon/lib/**`（可选的 DSH 适配壳，esbuild 单文件）**不入库** ——
由插件目录自带的 `.gitignore` 忽略；需要时 `npm run build` 生成。
这样仓库里不会有一份 48KB 的冗余 bundle。

## 4. 依赖整理

- **运行时零第三方依赖**：产品链路只允许 `node:*` 与仓库内相对 import。可执行证明：
  `standalone/test/verify-independence.mjs`（依赖传递闭包 **28 个文件 / 外部依赖 0 个**）。
- **构建期**：`typescript` + `esbuild` + `@types/node` → 列在 `requirements.txt`，
  声明在 `package.json` 的 `devDependencies`。`npm install` 装到本仓库，
  `rank20-daemon/build.mjs` 现在**优先查本仓库 `node_modules`**（仓库根或插件目录），
  不再需要任何外部检出（DSH checkout 只在显式设置 `DSH_CHECKOUT` 时才作为兜底）。
  实测：清空所有 `DSH_*` / `TSC_JS` / `ESBUILD` 环境变量后 `node build.mjs` 仍然成功。

## 5. 整理过程中顺带修掉的两个真问题

### 5.1 口径回归会随日期漂移（假失败）

`rank20-daemon/test-run.mjs 32 20260916` 用"最近 32 个工作日"的窗口去复算 9-16 榜。
**窗口锚在"今天"**，所以它会一直往前漂：到 2026-10-10 时窗口变成 `20260827…20261009`，
截到 cutoff 只剩 **15 个交易日**（< 需要的 21 个）→ 品种数 0、**命中 0/34**。

- 修法：给 `fetchAllExchanges(days, log, signal, from?)` 增加窗口锚点参数，
  `test-run.mjs` 传入 **cutoff 日期** → 窗口固定为 `20260804…20260916`，与运行日期无关。
- 实测：修完 **34/34** 全命中。

### 5.2 回归测试"永远绿"（更危险）

同一个 `test-run.mjs` 之前**无论命中多少都以退出码 0 结束** ——
`npm test` 这类聚合运行器会把"命中 0/34"判成 PASS。这比失败更糟。

- 修法：命中数 < 总数 → `process.exit(1)`；同时 `tools/run-tests.mjs` 额外解析
  `命中 X/Y` 文本，X≠Y 时即使退出码为 0 也判定 FAIL。
- 顺带把复算产物从 `rank20-daemon/rank20/` 移到 `rank20/regression/`，
  不再往插件目录里丢数据（历史上就是这么把仓库搞乱的）。

> 教训写在这里而不是只改代码：**测试必须有能力失败**，否则它提供的是虚假的安全感。

### 5.3 文档里的凭据（发布审计差点放过）

`docs/08-数据源补全报告.md` 里把大商所的 `apikey` 当成"JWT payload 实例"原样抄了下来。
**基于关键字/格式的模式匹配完全没命中它**（它长得不像 `KEY='...'`）。
这是第二次踩同一类坑，于是审计里加了最硬的一条 **A1b**：

```
拿 .env 里的每一个凭据值，去和仓库里每一个文本文件做全文比对 —— 有一处出现即失败
```

不再依赖"我能想到的泄漏格式"。加上这条后，凭据无论以什么形式出现（表格、日志、
payload、注释）都会被拦下。同时该值已从文档脱敏，并 `git commit --amend` 重写首发提交
（尚未 push，历史里没有残留 —— 用 `git grep <值> $(git rev-list --all)` 验证为空）。

## 6. 发布前自检（照着做一遍）

```bash
# ① 发布前审计：密钥 / 绝对路径 / 运行时产物 / 体积   → 应 10/10 通过
#    A1b 会用 .env 里的真实值反查整个仓库：任何格式的泄漏都能抓到
node tools/audit-publish.mjs

# ①b 远端审计：克隆 GitHub 上的仓库，扫描**所有 ref / 所有提交 / 所有 blob** + 提交元数据
#     并逐个比对 .env 的真实值（本地干净 ≠ 远端干净：已删除内容仍留在历史里）
npm run audit:remote

# ② 全部验收套件（--fast 跳过需要真实数据的）        → 应全绿
node tools/run-tests.mjs
node tools/run-tests.mjs --fast

# ③ 确认暂存清单里没有红线文件
git add -A && git status --short
git ls-files | Select-String -Pattern '\.env$|node_modules|^rank20/|\.docx|super-injector'
#   ↑ 期望：无输出（只有 .env.example 会被匹配到 —— 那是模板）

# ④ 提交并推送
git commit -m "chore: initial public snapshot"
git remote add origin <your-repo-url>
git push -u origin main
```

1. ✅ **git 身份**已设为仓库局部的姓名与邮箱（**邮箱不写进文档**，避免二次暴露；它只存在于提交元数据里，
   这是 Git 的正常行为，GitHub 会在提交页公开显示）。
2. ✅ **已添加 MIT 许可证**：`LICENSE`（Copyright (c) 2026 fyc），四个 `package.json` 的
   `license` 字段统一为 `MIT`（`rank20-daemon` 原为随手写的 `BSD-3-Clause`，已改正）。
3. ⚠️ **仓库可见性由你决定**：数据抓取与展示的合规边界是"局域网内部自用"（见 README「许可与免责」），
