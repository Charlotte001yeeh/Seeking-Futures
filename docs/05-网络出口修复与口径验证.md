## 第一部分 · 网络出口问题：已解决

### 1. 故障根因

最初表现为所有 HTTPS 请求 `curl exit 35`（连 `https://www.baidu.com` 都失败），容易误判为"网络被封"。**逐层排查后定位为 TLS 后端故障，与网络无关。**

| 排查层 | 命令/方法 | 结果 | 判断 |
| --- | --- | --- | --- |
| DNS | `Resolve-DnsName` | `www.shfe.com.cn → 220.248.39.134` | ✅ 正常 |
| TCP 连通 | `Test-NetConnection -Port 443` | `TcpTestSucceeded=True` | ✅ **网络通** |
| 代理配置 | 注册表 Internet Settings | `ProxyEnable=1, ProxyServer=127.0.0.1:7890` | ⚠️ 存在，但非故障源 |
| **TLS 握手** | `curl -v` | **`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)`** | ❌ **根因** |

**根因结论**：curl.exe 在 Windows 上使用 **Schannel** TLS 后端，当前沙箱环境下无法获取客户端凭证句柄，握手阶段即失败。与目标站点、DNS、网络策略均无关。

### 2. 绕行方案对比（全部实测）

| 方案 | 结果 |
| --- | --- |
| **Node.js v24.21.0（OpenSSL）** | ✅ **成功**：`https://www.shfe.com.cn/...kx20260915.dat` → `STATUS 200 / 123177 bytes` |
| curl `--ssl-no-revoke` | ❌ 仍 `code=000` |
| PowerShell `Invoke-WebRequest`（HttpClient） | ❌ `基础连接已经关闭: 接收时发生错误` |
| curl 换 openssl 后端 | 未提供该构建 |

### 3. 决定

> **采集器统一使用 Node.js 的 `https`/`http` 模块。禁止在采集路径使用 `curl.exe` 或 `Invoke-WebRequest`。**

附带好处：Node 与 DSH 运行时同栈，后续插件化零摩擦。

## 第二部分 · 口径验证：我们的算法与交易所官方值完全一致

这是"确保数据相同可信"从声明变成证据的关键一步。

### 1. 算法定义

```
涨跌幅(%) = (今收盘 − 昨结算) / 昨结算 × 100
```

### 2. SHFE 验证（2026-09-15 日报）

对 `kx20260915.dat` 全部有效合约，用官方 `CLOSEPRICE` 与 `PRESETTLEMENTPRICE` 自算涨跌幅，与官方自带字段 `ZD1_CHG`（涨跌1）对比：

### 4. 首次跑出的"100pct 异常"是什么

第一次跑 CZCE 时出现一条 `最大偏差 100.0000 pct`。**这不是数据问题，是我方解析缺陷**：

- 郑商所日报对**当日无成交**的合约，把 `今开盘/最高/最低/今收盘` 全部填 `0.00`，但仍给出 `今结算` 与 `昨结算`。
- 若不加判断地用 `(0 − 昨结算)/昨结算`，就得到 `−100%`。
- 定位后加入过滤（`close>0 && volume>0`），偏差立刻归零。

> **这一条直接产出了两个必须写进采集器的规则**（见 §第三部分 R1、R2）。

### 5. 交叉印证：基准不同会差多少

| 品种合约 | 交易所官方（昨结算为基） | 东方财富 clist（昨收为基） | 差额 |
| --- | --- | --- | --- |
| `TA610` | +3.65% | +4.29% | **0.64 pct** |

→ **坐实"涨跌幅必须以昨结算价为准，且要取官方结算价"。** 用东财 `f3` 直接当涨跌幅，会产生 0.6pct 级别的系统性偏差。

## 第三部分 · 由此新增的解析规则（回写采集器规范）

| # | 规则 | 依据 |
| --- | --- | --- |
| **R1** | **零成交合约必须过滤**：`成交量 == 0` 或 `今收盘 == 0` 的合约，其涨跌幅无意义（官方按 `close=0` 会算出 −100%） | CZCE 实测 50 条；CY610/CY612/CY702 等 |
| **R2** | **保留零成交合约的结算价**：官方对零成交合约仍给结算价（跌停/涨停板价），这是有效信息，只是**不参与涨跌幅排名** | 同上 |
| **R3** | **汇总行必须剔除**：SHFE `DELIVERYMONTH="小计"`；CZCE `小计`/`总计`；GFEX `variety="总计"` | 三所实测均有 |
| **R4** | **数字千分位清洗**：CZCE 文本含 `7,607.00` 形态，需先 `replace(/,/g,'')` 再转数值 | CZCE 解析 |
| **R5** | **GBK 解码**：CZCE 与 CFFEX 为 GBK 编码，需显式解码后再解析中文表头；数字与分隔符是 ASCII，可容忍"按 latin1 读+数值解析"的降级路径 | 实测 |
| **R6** | **字段名拼写陷阱**：GFEX 的成交量字段是 `volumn`（官方拼写错误），不是 `volume` | GFEX 实测 |
