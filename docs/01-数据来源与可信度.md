# 01 · 数据来源、可信度与获取方式

> 实测环境：`2026-09-16`（China Standard Time，日盘时段），在仓库根目录下运行（下文命令均以仓库根为当前目录）。
> 标注约定：**【实测✅】**= 本机真实返回了数据；**【实测❌】**= 调用失败；**【调研】**= 文档/资料结论；**【未核实】**= 未拿到确证。
>
> **需求锚点（见 `04-总设计.md §0.1`）**：本项目硬交付为 **D1 20日涨跌幅 rank20 + D2 幅度数据 + D3 日 K 线**（均须对齐文华）；
> **D4 因果分析不设数据要求**。因此本文档重点关注 D1-D3 所需字段（结算价、持仓量、成交量、OHLC），
> 持仓排名/仓单等属 **D4 可选增强**，缺失不阻塞。

## 0. 一条必须知道的硬约束：本机 HTTPS 不通

| 协议 | 结果 |
| --- | --- |
| `https://hq.sinajs.cn` | **【实测❌】** curl exit 35（SSL connect error） |
| `https://www.shfe.com.cn` | **【实测❌】** curl exit 35 |
| `http://hq.sinajs.cn` | **【实测✅】** 正常返回 |
| `http://push2.eastmoney.com` | **【实测✅】** 正常返回 |
| `https://www.baidu.com` | **【实测✅ 失败】** exit 35 |

`Test-Connection` 无回显、DNS 正常解析（`hq.sinajs.cn → 123.125.107.29`），因此**不是 DNS 问题，是本机/当前 shell 沙箱的 TLS 出站被拦**（可能是中间盒证书不被信任，或仅放行明文出口）。

影响与绕行：

1. 交易所官网（上期所/郑商所/大商所/广期所/中金所）几乎全是 HTTPS-only，**从 shell 直连拿不到**；实测上期所 `kx20260915.dat` 返回 `307 → https://...`，跟随重定向后 size=0。
2. 采集器落地时的三种选择（阶段 1 决策）：
   - **A. 只用明文可达源**（东财 + 新浪，均已实测可用）——最快、零配置。
   - **B. 给进程配 HTTPS 代理 / 导入企业根证书**——拿交易所官方数据，权威性最高。
   - **C. 用 harness 的 `web_fetch` 通道**做交易所页面的兜底抓取（已验证能取 HTTPS 页面）。
3. 无论哪种，**上线前必须重测一次本机出口能力**（可能只是当前沙箱策略，而非整机）。

## 1. 数据源分层与可信度评级

```
第一档  交易所官方      上期所/能源中心/大商所/郑商所/广期所/中金所   ← 结算价、持仓排名、仓单的"真值"
第二档  持牌行情商      文华财经 WT9(付费API) / 东方财富 / 新浪财经     ← 行情连续性好，字段经过加工
第三档  聚合与二手      各类免费 SDK(akshare 等)、资讯站              ← 便捷，但要多源交叉
```

### 评级表

| 源 | 档位 | 底层真值 | 实测状态 | 适合用途 | 主要风险 |
| --- | --- | --- | --- | --- | --- |
| 交易所官网（SHFE/INE/DCE/CZCE/GFEX/CFFEX） | ① 权威 | 自身 | **shell ❌ / HTTPS 通道 ✅**（见 §0 与 §2.6） | 结算价校验、**每日持仓排名**、**仓单日报**、库存周报 | shell 层 HTTPS 被拦需绕行；页面格式分散（dat/txt/csv/json） |
| 文华财经 WT9 历史数据服务 | ② 持牌 | 交易所+自有加工 | 未接入 | 与 wh6 界面**完全一致**的 K 线、tick | **付费**（K 线 3 万/年/交易所，tick+日线 6 万/年/交易所）；需 WT9 客户端在线；**只含历史不含当日**；**授权止于"终端接收"，无再分发/对外展示权** |
| 东方财富 push2 | ② 持牌 | 交易所行情 + 自有整理 | **✅ 实测可用** | **全市场排行（本次核心）**、日 K 线、实时快照 | 含"主连/次主连/指数"合成代码需过滤；无官方 SLA；有反爬史；**日K无持仓量、无结算价** |
| 新浪财经 hq.sinajs.cn + 日K接口 | ② 持牌 | 交易所行情 | **✅ 实测可用** | 实时快照、**单合约完整日 K 全历史（带持仓量）**、第二源校验 | 接口非公开契约；https 不通（本机）；`p` 持仓量字段在连续序列上曾返回 0 |
| akshare 等免费聚合 | ③ 聚合 | 转载上述各方 | 未安装 | 快速原型、拿交易所日报（`get_futures_daily` 直连交易所） | 接口随上游改版频繁失效；不可作为唯一来源 |
| 资讯/产业站（9qh 等） | ③ 二手 | 转载 | **❌ exit 6**（DNS/连接不可达） | 仅作新闻参考 | 不可作为数据源 |

> 结论：**官方交易所为一档基准（可对客展示）；文华/东财/新浪为二档（仅授权终端内使用）；免费聚合为三档（仅内部研究并标注"仅供参考"）。**
> 本项目落地顺序：**① 交易所官方拿真值（结算价/持仓量/持仓排名/仓单） → ② 东财做全市场排行与盘中快照 → ③ 新浪做第二源校验。** 文华 API 只有在"必须与客户 wh6 屏幕完全对齐"时才值得付费。

## 2. 已实测接口清单（可直接用于采集器设计）

### 2.1 【实测✅】东方财富 · 全市场涨跌排行（数据源 A）

```
GET http://push2.eastmoney.com/api/qt/clist/get
    ?pn=1&pz=50&po=1&np=1&fltt=2&invt=2&fid=f3
    &fs=m:113,m:114,m:115,m:8,m:142
    &fields=f12,f13,f14,f2,f3,f4,f5,f6,f15,f16,f17,f18,f20,f21
```

- `fid=f3` 按涨跌幅排序；`po=1` 降序（涨幅榜）/ `po=0` 升序（跌幅榜）。
- **【实测⚠️ 分页上限 100】** 传 `pz=1500` 也只返回 100 条（服务端硬上限），因此要拿全市场必须翻页：实测 **`pn=1..11, pz=100` 累计恰好取满 1020 条**。建议每次翻页间隔 ~300ms。
- **【实测⚠️ 缺失值为字符串】** 部分合约（多为无成交的远月）`f2/f3` 返回 `"-"` 而非数字，解析时必须容错，不能直接转数值。
- `fs` 市场段（实测总量 **1020** 个合约）：

| 段 | 实测 total | 含义 |
| --- | --- | --- |
| `m:113` | — | 上期所 SHFE |
| `m:114` | — | 大商所 DCE |
| `m:115` | — | 郑商所 CZCE |
| `m:8` | **72** | 中金所 CFFEX |
| `m:142` | **73** | 上期能源 INE（实测返回的是原油 sc 系列，与 GFEX 共段，**待细分**） |

- 返回字段字典（实测样本 `rb2610`：`f2=3071 f3=... f4`）：

| 字段 | 含义 | 字段 | 含义 |
| --- | --- | --- | --- |
| `f12` | 合约代码（`rb2610`/`rbm`/`TAS`） | `f17` | 今开 |
| `f13` | 市场段编号 | `f18` | 昨结 |
| `f14` | 中文名（`螺纹钢2610`/`螺纹钢主连`） | `f20` | 总市值（多为 `-`） |
| `f2` | 最新价 | `f21` | 流通市值（多为 `-`） |
| `f3` | **涨跌幅 %** | `f5` | 成交量（手） |
| `f4` | 涨跌额 | `f6` | 成交额（元） |
| `f15` | 最高 | `f16` | 最低 |

- **【实测⚠️ 关键坑】** 返回里混着合成序列：`rbm`=螺纹钢主连、`RSS`=菜籽次主连、`TAS`=PTA次主连、CFFEX 段有 `151103`=IM隔季连续。**必须按 `f12` 规律过滤**（末尾带月份数字的才是可交易合约），并把主连单独用作趋势参考。

- **【实测⚠️ 关键坑】** 榜首被极不活跃合约污染：实测涨幅第一 `RS709 菜籽709 +13.89%`，当日 `f5=1`（成交 1 手）、`f6=63780` 元；跌幅榜 `lu2707` 成交 2 手。**这说明东财"全市场排行"不能直接用** —— 必须每品种取主力合约后再排序（文华正是这么做的）。

### 2.1.1 【实测✅】全市场结构（2026-09-16 14:38，11 页翻页结果）

| 指标 | 实测值 |
| --- | --- |
| clist 返回总数 | **1020** |
| 正则 `^[a-zA-Z]{1,3}\d{3,4}$` 判定为可交易合约 | **666** |
| 剔除的合成序列（主连/次主连/连续/指数） | 约 354 |
| 去重后品种数 | **69** |
| 其中当日成交额 ≥ 1 亿的品种 | **64** |

**结论：全国商品期货"可交易品种"只有约 69 个** —— 所以 rank20 **必须每品种取当日主力合约**，否则会出现同一品种多个月份霸榜（实测跌幅榜曾被沪镍占据 6 席、玻璃 5 席、苹果 4 席）。这与文华"只列主力合约"的做法一致。

### 2.1.2 【实测✅】过滤后成品榜（品种级 · 主力合约 · 成交额≥1 亿）

见 `docs/02-分析框架与输出规范.md` §3.3 的实测表。要点：涨幅侧能化 9 个品种共振，跌幅侧农产品/黑色建材分散无共振 —— 这正是因果分析要区分的"共振 vs 个股基本面"。

### 2.1.3 【实测⚠️】主力合约判定不能只用成交额

实测矛盾案例：`ta` 品种当日成交额最大的是 **TA701（662 亿，+1.93%）**，但成交额/涨幅更大的 **TA610（86 亿，+4.29%）与 TA611（201 亿，+4.02%）** 同时存在。若按"成交额第一"取主力，会得到 TA701（+1.93%），与该品种真实强势月份（+4.2%）**差 2 个百分点以上**。

**修正建议**：主力判定用 `0.5×持仓量排名 + 0.5×成交额排名`，或直接采信东财返回的"主连"成员关系再回溯到可交易合约；并把"该品种当日各月份涨跌幅分布"一并落库（用于月差与换月分析）。


### 2.2 【实测✅】东方财富 · 日 K 线（主连与单合约）

```
GET http://push2his.eastmoney.com/api/qt/stock/kline/get
    ?secid=113.rbm&klt=101&fqt=0&lmt=5&end=20500101
    &fields1=f1,f2,f3,f4,f5,f6
    &fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
    &ut=fa5fd1943c7b386f172d6893dbfba10b
```

- `secid` 规则：`<市场段>.<代码>`，如 `113.rbm`（螺纹钢主连）、`115.TAm`（PTA主连）、`114.im`（铁矿石主连）、`113.rb2610`（单合约）。**【实测❌】** `113.rb0`、`113.rb2601` 返回 `rc:100, data:null` —— 主连用后缀 `m`，**单合约代码必须小写且为实际挂牌月份**。
- 实测返回样例（`113.rbm`，5 条日线）：

```
"2026-09-14,3106,3095,3110,3088,643026,19919084032,0.71,-0.71,-22,0.00"
"2026-09-15,3095,3110,3115,3089,723756,22463288064,0.84,0.42,13,0.00"
"2026-09-16,3113,3128,3136,3111,718895,22475920350,0.81,0.81,25,0.00"
```

- 字段顺序（`fields2=f51..f61`）：`日期, 开, 收, 高, 低, 成交量, 成交额, 振幅%, 涨跌幅%, 涨跌额, 换手率%`。
- **注意：东财日 K 不含持仓量**，持仓量必须从快照（`f47` 见 2.3）或交易所日报补齐。

### 2.3 【实测✅】东方财富 · 单合约实时快照（含持仓量）

```
GET http://push2.eastmoney.com/api/qt/stock/get?secid=113.rbm
    &fields=f43,f44,f45,f46,f47,f48,f57,f58,f60,f107,f108,f169,f170,f171
```

实测（14:38 日盘中）：`f43=3128(现价) f44=3136(高) f45=3111(低) f46=3113(开) f47=718972(成交量) f48=22478328660(成交额) f58=螺纹钢主连 f60=3110(昨结) f107=113(市场段) f169=25(涨跌额) f170=81(涨跌幅×100) f171=72(振幅×100)`。

- **实测发现的精度坑**：`f170/f171` 是**放大 100 倍**的整数（81 → 0.81%），而 clist 的 `f3` 是直接百分数。两个接口口径不同，采集器必须统一。

### 2.4 【实测✅】新浪财经 · 全历史日 K（第二源 / 单合约）

```
GET http://stock2.finance.sina.com.cn/futures/api/jsonp.php/var%20x=/InnerFuturesNewService.getDailyKLine?symbol=RB0
Referer: https://finance.sina.com.cn
```

- 返回 `[{d,o,h,l,c,v,p,s}, ...]`：`d`=日期、`o/h/l/c`=开高低收、`v`=成交量、**`p`=持仓量**、`s`=结算价（实测连续序列该字段为 `0.000`，单合约待验）。
- `symbol` 同时支持**主连**（`RB0`，实测数据起点 **2009-03-27**，1131+ 条，长度 515KB）与**具体月份合约**（`RB2601`，实测起点 **2025-01-16**，长度 28.9KB；大小写不敏感）。
- 实测覆盖：`RB0`、`TA0`（起点 2006-12-19）、`RB2601` 均正常 —— 这是**最省事的"合约级日 K 全历史"来源**，且**带持仓量**，正好补东财日 K 缺持仓量的短板。
- 缺点：JSONP 包裹、无官方契约、一次性返回全量（大品种 500KB+），需缓存。

### 2.5 【实测✅】新浪财经 · 实时快照（多合约批量）

```
GET http://hq.sinajs.cn/list=nf_RB0,nf_I0,nf_TA0,nf_M0,nf_AU0,nf_SC0
Referer: https://finance.sina.com.cn
```

- 返回 GBK 编码字符串（需转码），实测 `nf_RB0="螺纹钢连续,时间,开,高,低,昨收,买价,卖价,最新价,昨结,昨持仓,...,日期,..."`，一次请求可取多合约。
- 用途：**与东财做同分钟交叉校验**（同一时刻两个源的现价/涨跌幅偏差 >0.1% 即告警）。

### 2.6 【实测部分✅】交易所官方接口（一档真值源）

> 关键发现：**交易所 HTTPS 在 shell 层全部失败（curl exit 35），但通过 harness 的 HTTPS 通道可以正常取到完整数据。**
> 因此阶段 1 的采集器**必须解决 HTTPS 出口**（代理/证书），或让采集走一个具备 HTTPS 能力的进程。这是本项目唯一的硬性环境阻塞点。

## 3. 主力合约与"主力连续"口径（关键，直接影响涨跌幅计算）

### 3.1 概念法定含义（红塔期货投教）

- **主力合约**：**持仓量与成交量最大**的近期交割月合约；随移仓换月而变（例：沪金 2509 → 2512）。
- **主连（主力连续）**：把不同时期的主力合约按时间**拼接**成的连续价格曲线，**不可交易**，只作行情参考。
- **加权/指数**：把同一品种所有月份合约按规则加权汇总，反映品种整体。
- **换月动因**：期货有到期/交割日，自然人不能进交割月交割，临近交割月时资金从当前主力移向下一主力。

### 3.2 各家口径实测对照（含三家换月规则）

| 源 | 主连代码形态 | 实测 | **换月规则** | **复权** |
| --- | --- | --- | --- | --- |
| **新浪** | `RB0`（另有 `88`/`888`） | **✅ 全历史** | **持仓量最大者为主力；其他合约收盘后持仓超当前主力 1.1 倍**才从次一交易日起切换，日内不换 | `88`=简单拼接**未平滑**；`888`=**平滑**（按 T-1 新旧主力收盘价差整体平移历史价格，**成交额置 0**） |
| **东方财富** | `113.rbm` / `115.TAm` / `114.im` | **✅ 可日 K** | 主力=**成交量最大**、**只向前切换不回退**、**每日收盘结算后判断**；另有按交割月排序的 00/01/02 连续 | **不复权**拼接（实测 K 线无跳空修补痕迹） |
| **文华 wh6/WT9** | "主连"标识 | 【调研】 | 各月份合约**掐头去尾**（仅保留其主力期间的 K 线）后按时间拼接 | **完全不复权**；官方明说"主力换月时有很大的价格跳空，造成趋势失真" |
| CFFEX 段 | `151103`=IM隔季连续 | ✅ 出现在列表 | — | — |

**依据**：新浪/`88`/`888` 口径见 AKShare 期货文档；文华自述见 WT9 说明书"主连链回测"节；东财口径见其数据文档"连续合约"节。

> **风险（必须写进设计）**：
> 1. **未复权主连在换月日会产生虚假大涨/大跌**（三家未复权源：文华、东财、新浪 `RB0`）；
> 2. **各家自算的 `pct` 在换月日互不可比**——同一品种同一天，三个数据源可能给出三个涨跌幅；
> 3. `888` 式平滑虽改善了绝对价格，但**成交额被置 0 且历史价格被改写**，用其计算历史涨跌幅会与真实记录口径冲突；
> 4. **禁止**把"平滑序列"与"未复权官方价"直接作差，也**禁止**把不同档位的源拼进同一条序列。

> 因此本项目设计为：**rank20 用"当日真实主力月份合约"计算，主连仅用于长周期走势展示，并显式标注"未复权"。**

> 另一条实测交叉验证：郑商所官方日报显示 `TA610 昨结算 6,680 → 今收盘 6,924（涨跌1 = +244，即 +3.65%）`，而东财 clist 同一时刻给 `TA610 +4.29%`。两者**基准不同**（官方涨跌1以昨结算为基，东财以昨收为基），差异达 0.6pct。**这坐实了 DQ-4：涨跌幅必须以"昨结算"为基准，且需要从官方源取结算价。**

> **换月跳空的处理原则**：
> 1. **rank20 用"当日真实主力合约"（可交易代码）计算，不要用主连**；
> 2. **日 K / 趋势判断才用主连**，且必须记录每次换月日期；
> 3. 若两源主连换月日不同，同一"品种"的历史涨跌幅会有差异 —— 这是口径差，不是数据错。

### 3.3 本项目建议口径（写死）

1. **rank20（D1/D2）**：每品种先按文华官方规则判定当日主力合约（量+仓双料最大、维持原则，见 `04 §3.2`），再用该合约计算当日与 20 日涨跌幅，排序取前 20。
2. **日 K 序列（D3）**：同时落库三份 —— ① 主力连续（趋势用，标注未复权）、② 当日主力合约（真实可交易）、③ 该品种全月份合约原始日 K（换月与价差分析用）。
3. **换月检测**：每日记录各品种"成交额最大的合约"，若与昨日不同，落一条 `rollover` 事件，供模型与分析层引用。
4. **每条记录必备 6 个元数据字段**：`source`、`fetch_time`、`trade_date`、`contract`（真实月份合约，不是主连代码）、`is_main`、`adjusted(bool)`。缺任一项则无法复盘口径。

## 4. 数据质量规则（从实测坑反推，采集器必做）

| # | 规则 | 依据 |
| --- | --- | --- |
| DQ-1 | **零成交合约必须排除出排名**：`成交量==0` 或 `今收盘==0` 时不参与（官方 `close=0` 会算出 −100%）；**但其结算价保留** | 实测 CZCE 50 条零成交合约；见 `05 §第三部分 R1/R2` |
| DQ-2 | **合成代码过滤**：剔除中文名含"主连/次主连/连续/加权/指数"或代码非"字母+数字"的项 | 实测 `rbm/TAS/RSS/151103` |
| DQ-3 | **同品种去重**：一个品种当日只保留成交额最大的一个月份合约 | 实测排行榜同一品种多月份并列 |
| DQ-4 | **涨跌幅基准统一为"昨结算价"**（国内期货惯例），并**优先用交易所日报的结算价**自算 | **实测坐实**：郑商所官方 `TA610` 涨跌1=+244（+3.65%），东财 clist 同刻给 +4.29%，差 0.6pct |
| DQ-5 | **盘中/收盘态标记**：日盘 15:00 前数据是未定稿的日内快照，须打 `intraday` 标记，不能用它生成"每日榜" | 本次实测时间 14:38 仍在交易中 |
| DQ-6 | **夜盘归属**：夜盘（21:00–次日 02:30）计入**下一交易日** | 交易所规则 |
| DQ-7 | **三源校验 + 偏差阈值**：`|Δclose|/close > 0.5%`、`|Δvolume|/volume > 5%`、持仓量方向不一致、结算价缺失 → 告警并落"可疑"标记；**换月日单独放行阈值并记 `rollover` 事件** | 需要官方+新浪+东财三方互校 |
| DQ-8 | **缺失即标记，不插值**：主力换月、涨跌停、停牌合约不得用插值填充 | 避免污染模型输入 |
| DQ-9 | **翻页取全**：clist 单页上限 100，必须 `pn=1..11` 取满 1020 条后再本地过滤 | 实测传 `pz=1500` 仍只回 100 条 |
| DQ-10 | **品种级聚合**：榜单先去重到"品种 × 当日主力合约"，再排序取前 20 | 实测同品种可占 6 席 |
| DQ-11 | **主力判定增补持仓量**：仅用成交额会漏掉真实强势月份（实测 ta 相差 >2pct） | 见 §2.1.3 |
| DQ-12 | **主力判定按文华官方规则**：量+仓**双料最大**，否则**维持原主力**；两项均非第一才让位给量最大者。**禁止沿用东财"成交量最大且只向前"口径** | 实测 09-16 沥青东财选 `bu2610`、文华口径应为 `bu2611`；见 `06 §1` |
| DQ-13 | **rank20 需标注 `rolled_over`**：20 日窗口内换月的品种，其 20 日涨跌幅含换月跳空，是名义值 | 见 `04 §3.5.4` |
| DQ-14 | **多口径并存落库**：当日涨跌幅（昨结/昨收两种基准）与 20 日涨跌幅（主连/同合约）**全部落库**，便于对账与随时切换 | 口径未定标前的必要冗余，见 `04 §3.5.2` |
