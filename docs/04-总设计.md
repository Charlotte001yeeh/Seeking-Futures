## 1. 网络出口：根因与解决方案 ✅ 已解决

### 1.1 根因（实测定位）

## 2. C2 关键澄清：什么叫"与文华数据一致"

这一条必须先讲清楚，否则会做错方向。

### 2.1 事实链

```
交易所（真值源）
   ├──→ 文华财经（拿到授权，加工后显示在你的 wh6 屏幕上）
   ├──→ 东方财富 / 新浪（同样转载交易所）
   └──→ 本项目（直接取交易所）
```

**文华的期货行情本质就是交易所行情**，文华自己不生产价格。因此：

> **取交易所官方数据 ≠ 与文华不一致；恰恰相反，交易所是文华的上游，同源同值。**

真正需要"复现"的不是原始行情，而是**文华在原始行情之上自有的计算与规则**。这些才是会产生偏差的地方。

### 2.2 文华"自有加工"清单与我们的对策

| 文华显示的东西 | 来源性质 | 本项目对策 |
| --- | --- | --- |
| 开/高/低/收/结算价/成交量/持仓量/涨跌 | **交易所原始值**，文华直传 | 直取交易所，**天然一致** |
| **主力合约标识（"主"）** | **文华自有规则** | **必须复现其规则**（§3.2） |
| **20 日涨跌幅** | **文华自有窗口口径** | **✅ 已定标并复现**（§3.5.5）—— **D1 核心** |
| 主连 / 加权 / 指数 | **文华自有拼接算法** | 主连复现（§3.3）；加权/指数本期不做 |
| **排名列表的成员与顺序** | **文华自有过滤+排序** | **必须复现其过滤与排序**（§3.4） |
| 均价 / 主动买卖比例 Scale / 资金流 | **文华自有计算** | 官方日线不含，**本期不复现**，明确标注"无此字段" |
| 逐笔 tick 级明细 | 交易所授权 + 文华加工 | 需付费，**本期不取**；日线级已满足 D1/D2/D3 |
| 资讯/快讯 | 文华采编 | 本期不做，避免与行情数据混淆 |

### 2.3 因此"与文华一致"的可执行定义

> **一致 = 取交易所官方真值（与文华同源）+ 复现文华的四项自有规则（主力判定、20 日窗口口径、榜单过滤、涨跌幅基准）= 屏幕上与文华一致。**

这比"去抓文华的网页/客户端"更可靠：不依赖反爬对抗，不触碰再分发合规红线，且**可验证**（§6 校准闭环）。

## 3. 口径算法规范（核心，决定 A1/A2 能否通过）

### 3.1 涨跌幅基准（可配置，见 §3.4.2）

```
涨跌幅(%) = (今收盘 − 昨结算) / 昨结算 × 100      ← 默认（prev_settle）
涨跌幅(%) = (今收盘 − 昨收盘) / 昨收盘 × 100      ← 备选（prev_close，匹配 wh6 个性化设置）
```
- **默认用昨结算**。实测证据：郑商所官方 `TA610` 涨跌1 = +244（以昨结算 6,680 为基 → +3.65%），而东财 clist 同刻显示 +4.29%（以昨收为基），差 **0.64pct**。
- **必须做成配置项**：文华客户端的基准由个性化设置决定（昨收盘/昨结算，按交易所联动）。对账前先确认用户设置。
- 昨日结算价优先来自**交易所日报**（SHFE `SETTLEMENTPRICE` / CZCE `今结算` / GFEX `clearPrice`），缺失时才回退到本地库中前一交易日记录。
- **✅ 算法已通过验证**：用本公式自算，与交易所官方自带涨跌幅字段对比，**SHFE 301 条 + CZCE 188 条，最大偏差 0.0000pct，零异常**（见 `05`）。

### 3.2 主力合约判定（复现文华的"主"）—— ⚠️ 已按官方规则修正

> **重要修正**：v1 初稿用的是"持仓量最大 + 次主力超 1.1 倍切换"，这是**错的**。文华官方规则帖给出了成文规则，两者完全不同。

#### 3.2.1 文华官方规则（原文要点）

| # | 规则 |
| --- | --- |
| 1 | 每个品种**只选唯一一个**主力合约 |
| 2 | **日成交量与持仓量"双料最大"**的合约 → 新主力，**下一交易日**切换指向 |
| 3 | 未满足第 2 条前，维持原主力**不变** |
| 4 | 若当前主力的成交量与持仓量**都不是最大** → 下一交易日让位，新主力指向**成交量最大**的合约 |
| 5 | **无任何倍数阈值**；**无"次主力"概念**（官方明确否认） |
| 6 | 切换在**盘后执行、次日生效**；盘中即使满足也不即时切换 |

#### 3.2.2 实现（修正后）

```
输入：该品种当日全部挂牌月份合约的 (成交量, 持仓量)
状态：main ← 上一交易日的 main（跨日持久化）

step 1  令 dual  = 同时满足「成交量排名第1」且「持仓量排名第1」的合约（0 或 1 个）
step 2  若 dual 存在：
           若 dual ≠ main → 记 rollover(main → dual, reason="dual_max")，main ← dual
           若 dual == main → 维持
step 3  若 dual 不存在（量最大与仓最大是不同合约）：
           令 volMax = 成交量第1名
           若 main 仍「成交量第1 或 持仓量第1」 → 维持 main（规则 3）
           否则（main 两项均非第一） → 记 rollover(main → volMax, reason="degraded_volmax")，main ← volMax
step 4  切换一律次日生效，盘中不漂移
```

**冷启动**（库中无 main 状态时）：取当日 `dual`；若无 `dual`，取成交量第 1 名。

#### 3.2.3 实测验证（2026-09-08 ~ 09-15，上期所 6 个交易日）

| 检验项 | 结果 |
| --- | --- |
| 按上述规则跑 6 日全品种 | **触发换月 0 次** |
| "当前主力 == 双料最大" 的天数 | 101 |
| "当前主力 ≠ 双料最大" 的天数 | **29 —— 且规则 3 全部正确维持了原主力** |
| 上期所品种中「量最大 ≠ 仓最大」的品种 | **7/25**（al、zn、au、ag、ss、bu、br） |

**关键发现**：这 7 个品种正是**换月过渡期**的品种——近月合约成交量领先（投机资金还在），远月合约持仓量领先（产业资金已移仓）。例如沥青：

```
bu2611   成交量 296,894 (#2)   持仓量 255,342 (#1)   ← 仓最大
bu2610   成交量 710,945 (#1)   持仓量 156,698 (#2)   ← 量最大
```
`量最大 ≠ 仓最大` → 无 `dual` → 规则 3 维持原主力 `bu2611` 不变。

> **这恰好解释了为什么"6 日 0 次换月"是对的**：这正是文华规则设计的精髓——**宁可不换，也不在过渡期乱切**。同时也说明文华榜上的 `bu` 涨跌幅用的是**仓最大合约**而非量最大合约，与东财"成交量最大"口径**存在系统性差异**（实测东财 09-16 选中的是 bu2610）。

#### 3.2.4 与东财口径的差异（必须记录）

| | 文华 | 东方财富 |
| --- | --- | --- |
| 主力判定 | **量+仓双料最大**，否则维持 | **成交量最大** |
| 切换方向 | 可退可进（按规则） | **只向前，不回退** |
| 切换时点 | 盘后确认、次日生效 | 每日收盘结算后 |

→ **所以"用东财数据对齐文华"在换月过渡期必然失真**。本项目用官方日报自己算主力（§3.2.2），不使用东财的主力标记。

### 3.3 主连拼接（复现文华的"主连"）—— ⚠️ 已按官方说明修正

```
主连序列构造：
  对每个交易日 t：
      main(t)   = 当日主力合约（见 3.2.2，跨日状态机）
      K线(t)    = main(t) 当日的真实 OHLC
  拼接即得「主连」

"掐头去尾"规则（文华官方口径）：
  对每个合约，仅保留它【担任主力期间】的 K 线；
  主力期之前与之后的 K 线一律砍掉，再按时间顺序拼接。
```
- **完全不提供前/后复权**（文华官方说明书明确；wh6/wh7/wh8 均无复权选项）。
- 文华官方**自认**该处理"破坏了 K 线趋势的连续性和完整性……造成主力月份切换时有很大的价格跳空，造成趋势的失真……**不适合直接用于策略回测**"。
- **我们复现它，而不是修好它** —— 修好反而与文华不一致。

**同时额外落一份"复权主连"**（价格平移法）作为**本项目的增值字段**，供长周期趋势使用，必须：
- 显式标注 `adjusted=true`；
- **不得与未复权序列混入同一序列**；
- 前端展示必须带复权标记。

> ⚠️ **传闻澄清**：社区有文章称"文华 888 是复权主连"，但该说法来自第三方博客，**与文华官方说明书"完全不复权"直接冲突，判定为不可采信**。若后续要引入平滑序列，必须先在 wh6 上实测比对，不得默认其为文华口径。

### 3.3.1 加权 / 指数（本期不实现，仅登记定义）

| 概念 | 文华定义 |
| --- | --- |
| **加权** | 各月份合约价格按**持仓量加权平均**（`Σ(最新价×持仓量)/Σ持仓量`），映射主力月份走势，**无跳空** |
| **指数** | 各月份合约按持仓量加权，反映品种整体，曲线更平滑 |
| **次主连** | **文华不提供**（无次主力概念） |

→ **本项目不生成"次主连"**；东财返回的 `TAS`/`RSS`/`brs` 等"次主连"代码属于其自有合成，**必须过滤掉，不得与文华口径混用**。

### 3.4 榜单口径（复现文华的"主力合约排名"）—— ⚠️ 已修正

```
综合排名（涨幅榜 / 跌幅榜）：
  1. 候选集 = 各品种的【当日主力合约】（每品种恰 1 个）
              + 金融期货（股指/国债）      ← 文华综合排名含它们
              − 指数 / 主连 / 加权 / 次主连（文华综合排名不含）
  2. 计算涨跌幅（基准见 3.1，可配置）
  3. 排序：涨幅榜降序取前 20；跌幅榜升序取前 20
  4. 并列处理：同涨跌幅按成交额降序（稳定排序）
```

#### 3.4.1 关于流动性过滤：**默认关闭**

文华官方**明确没有**流动性过滤，甚至承认这个缺陷：

> "有些个合约成交量极其稀少，有价无市，但却占据了综合排名中涨跌幅排名榜首位置"（用户反馈稻谷、纤板）

因此本项目采取**双模式**：

| 模式 | 说明 | 用途 |
| --- | --- | --- |
| `reconcile`（对账模式，**默认**） | **不加任何过滤**，与文华逐项对齐 | 满足验收 A2；证明口径一致 |
| `analysis`（分析模式） | 加流动性阈值（首版：成交额 ≥ 1 亿元） | 喂给模型分析，避免噪声 |

- 阈值可配置；两种模式的产出**分别落库并标明 `filtered_by_liquidity`**。
- 前端默认展示 `analysis` 榜，但提供"文华同口径"切换按钮。
- **A2 的验收方式**：用 `reconcile` 模式跑，与 wh6 屏幕成员比对，重合度应 ≥19/20。

#### 3.4.2 涨跌幅基准是可配置的（重要）

文华客户端的涨跌幅基准由 **个性化设置** 决定：可选 **昨收盘** 或 **昨结算**，勾选后**按交易所整体联动**。

→ **本项目必须做成配置项** `pct_basis: prev_settle | prev_close`，**按交易所分别配置**，以匹配用户 wh6 的实际设置。

- **默认值**：`prev_settle`（国内期货惯例，也是交易所日报的口径，且已验证偏差 0.0000pct）。
- **对账时**：先确认用户 wh6 的设置，再切到对应基准。**这是 A1 能否通过的前置条件**——基准选错，全榜偏移 0.6pct 级别。

### 3.4.3 其他已知差异点

| 点 | 文华行为 | 本项目对策 |
| --- | --- | --- |
| 刷新 | 实时，**5 秒**自动刷新 | 盘后定稿为准；盘中模式可作为可选增强 |
| 夜盘 | **夜盘不计算白盘合约**（客服承诺落地） | 夜盘数据归属下一交易日；避免用夜盘价算白盘合约涨跌幅 |
| 速涨/速跌 | 快捷键 67/68，**算法窗口官方未公开** | **不复现**（未核实，不猜测） |
| 排序快捷键 | 60 恢复 / 61 涨幅 / 62 跌幅 / 63-66 量额 / 67 速涨 / 68 速跌，**不可自定义** | 仅作知识登记 |

### 3.5 涨跌幅排名（本项目主目标）—— 三种"涨跌幅"口径

> **用户需求已明确：最终交付物 = 与文华「主力合约报价」列表中给出的涨跌幅排名一致。**
> 注意：文华行情列表里存在**多个不同的涨跌幅字段**，必须区分，否则永远对不上。

#### 3.5.1 三种字段的定义（已确认）

| 字段 | 公式 | 状态 |
| --- | --- | --- |
| **当日涨跌1** | `(今收盘 − 昨结算) / 昨结算` | ✅ 已验证，与官方值偏差 0.0000pct |
| **当日涨跌2** | `(今结算 − 昨结算) / 昨结算` | ✅ 官方日报自带（SHFE `ZD2_CHG` / CZCE `涨跌2`） |
| **20日涨跌幅** | `(今日收盘 − 基准日结算价) / 基准日结算价` | ✅ **已定标（33/33 验证通过）** — 见 §3.5.5 |

文华官方公式函数表中，`REF(X,N)` 定义为"引用 X 在 N 周期前的值"（例：`REF(CLOSE,5)` = 当前周期前 5 个周期的收盘价）。
20 日涨跌幅的公式本体为 `(C − REF(C,20)) / REF(C,20) × 100`。**真正的分歧不在公式，而在"基准序列是什么"。**

#### 3.5.2 20日涨跌幅的 5 个候选口径（实测数据已备齐）

| 候选 | 口径 | 说明 |
| --- | --- | --- |
| **A** | 主连·收盘·REF20 | 在未复权主连上取收盘价，回溯 20 个交易日 |
| **B** | 主连·结算·REF20 | 同上但用结算价 |
| **C/D** | 主连·收盘·REF19 / REF21 | 检验"日"是交易日还是自然日近似 |
| **E** | **同合约·REF20** | 用**当前主力合约自身**的 20 日前收盘（不跨换月；区间内换月则无定义） |

**实测对照表（上期所，2026-09-15 收盘，主力按文华规则判定）**

| 品种 | 主力 | A 主连收盘20 | B 主连结算20 | E 同合约20 | 20日内换月 |
| --- | --- | --- | --- | --- | --- |
| rb | rb2701 | **+2.88%** | +3.12% | — | 是 |
| cu | cu2610 | **−0.83%** | −0.97% | — | 是 |
| sc | sc2611 | **+43.40%** | +45.32% | — | 是 |
| bu | bu2610 | **+30.56%** | +31.26% | +30.56%（一致） | 否 |
| al | al2610 | **+0.67%** | +0.46% | +0.67%（一致） | 否 |
| ag | ag2610 | **−3.42%** | −4.14% | −3.42%（一致） | 否 |
| fu | fu2611 | **+9.22%** | +11.00% | — | 是 |
| ni | ni2610 | **−3.72%** | −3.30% | — | 是 |
| sn | sn2610 | **−7.76%** | −7.24% | — | 是 |
| au | au2610 | **−2.79%** | −3.05% | −2.79%（一致） | 否 |

**观察**：未换月的品种上 A 与 E 完全一致（bu/al/ag/au 四行已验证）；**只有跨换月的品种才能区分口径**（rb/cu/sc/fu/ni/sn）。
→ **定标必须用换月品种**，用未换月品种无法区分 A 与 E。

#### 3.5.3 定标流程（与用户 wh6 对账）

> **前置澄清**：文华的排名数据**无法从外部获取**（无公开接口、免费版不能导出、付费 API 也不提供、逆向禁止）——完整核查见 `07-文华排名数据可获取性结论.md`。
> 因此"定标"不是让用户参与计算，而是**用一个观测值确认一个未知算法参数**。确认一次后，全流程纯自动化。
>
> 为什么会有未知参数：20 日窗口内若发生主力换月，"20 天前的价格"取**当时的主力合约**（主连口径，含换月跳空）还是取**当前合约自身**（同合约口径，不含跳空），结果不同。此信息只存在于文华客户端算法内部。

1. 本系统产出候选表（§3.5.2 格式）。
2. 用户在 wh6「主力合约报价」列表读出 **20 日涨跌幅**列的实际数值（**仅换月品种有效**）。
3. 匹配候选 → 锁定口径 → 写入配置 `pct20_method: A|B|E`。
4. 用 3 个以上换月品种交叉确认，避免巧合。
5. **之后不再需要任何人工读数**：同一算法自动覆盖全部品种与全部历史。

**配置项（写入 `config/`）**

```yaml
pct:
  basis_daily: prev_settle      # 当日涨跌幅基准：prev_settle | prev_close（按交易所可覆盖）
  method_20d: main_continuous    # 20日口径：main_continuous(主连) | same_contract(同合约)
  price_20d: close               # 取价：close | settle
  periods_20d: 20                # 周期数：20（交易日）
```

#### 3.5.4 20日排名的产出结构

```
主力合约 20日涨跌幅排名：
  候选集 = 各品种当日主力合约 + 金融期货（商品与金融混合排序）
           含 DCE 月均价期货（F 后缀）
  指标   = 20日涨跌幅（按 §3.5.2/§3.5.3 锁定口径）
  榜单   = 降序取前 20（涨幅）/ 升序取前 20（跌幅）
  输出   = {rank, variety, main_contract, pct_20d, pct_1d, close, base_settle, base_date}
```
> 因采用"同合约、不拼接"口径，**不需要 `rolled_over` 名义值提示**——序列内无换月跳空。

### 3.5.5 ★ 已锁定口径（2026-09-16，验证 33/33）

> 以下为**实测定标结果**，用户确认榜单正确。完整验证记录见 `09-20日涨跌幅rank20完整版.md`。

```
20日涨跌幅 = (今日收盘价 − 基准日结算价) / 基准日结算价 × 100
```

| # | 规则 | 说明 |
| --- | --- | --- |
| **R1** | 分子 = **今日收盘价** | 盘中读取时即"最新价" |
| **R2** | 分母 = **基准日结算价**，基准日 = **T−20** | T=2026-09-16 时基准日为 **08-19** |
| **R3** | **例外**：该合约 T−20 **无成交** → 基准前移到最近有成交日 | 实测菜籽 RS611（08-19 仅 5 手）、胶合板 BB2611（仅 4 手）→ **08-18** |
| **R4** | 主力合约 = **T−1 日成交量最大者** | 不可用 T 日（换月日会差一天） |
| **R5** | **跨换月不拼接**：用当前主力合约自身的价格序列 | 窗口内 17 个品种换月，但计算不拼 |
| **R6** | **包含月均价期货**（`F` 后缀） | 否则聚丙烯/聚乙烯月均价缺失 |
| **R7** | **商品与金融期货混合排名** | 沪深300 IF2609 进入跌幅榜 |

**已废弃的候选口径**（早期探索，均错误）：

| 候选 | 口径 | 结论 |
| --- | --- | --- |
| A/B | 主连·收盘/结算·REF20 | ❌ 偏差达 −2.56/+1.55/−0.26 |
| C/D | 主连·REF19/REF21 | ❌ |
| 按 K 线条数倒数第 20/21 条 | — | ❌ 各合约序列长度不一，锚点被带偏（碳酸锂曾算成 −18.39%） |

**正确做法**：从官方日报建**基准日结算价映射**，按合约代码直接取值。

**配置项（写入 `config/pct.yml`）**

```yaml
pct:
  basis_daily: prev_settle     # 当日涨跌幅基准：prev_settle | prev_close（按 wh6 个性化设置）
  pct20:
    method: same_contract      # 同合约（不拼接）—— 已定标
    base_offset: 20            # T-20
    base_price: settle         # 基准取结算价
    quote_price: close         # 今日取收盘价（盘中=最新价）
    zero_volume_fallback: true # T-20 无成交则前移到最近有成交日
  main_contract:
    rule: t_minus_1            # 用 T-1 日数据判定主力
    criterion: volume_max      # 成交量最大（双料最大优先，否则维持）
  universe:
    include_financials: true   # 商品 + 金融混合排名
    include_monthly_avg: true  # 含 DCE 月均价期货（F 后缀）
```

**主力判定的 T−1 规则（关键）**

```
main(T) = 用 T−1 日的量仓排名确定：
  ├─ T−1 存在"量+仓双料最大"合约 → 该合约
  ├─ 否则若原主力在 T−1 仍是量第1或仓第1 → 维持原主力
  └─ 否则 → T−1 的量最大合约
```

实测证据（不锈钢 ss）：09-15 为过渡日（量最大 ss2610、仓最大 ss2611，无双料）→ 09-16 主力维持 **ss2610**（与文华一致）。若用 T 日数据会误判为 ss2611。

## 4. 数据契约

### 4.1 铁律元数据（每条记录必备）

```
source       数据来源标识（如 "shfe_daily" / "czce_daily" / "gfex_loadList" / "em_clist"）
fetch_time   抓取时间（ISO8601，带时区）
trade_date   交易日
contract     真实月份合约代码（如 rb2610），禁止填主连代码
is_main      是否为该品种当日主力
adjusted     价格是否经过复权（仅主连序列有意义）

# 排名类记录额外必备：
pct_basis    涨跌幅基准（prev_settle | prev_close）—— 口径不写清则无法复盘
rolled_over  20 日窗口内是否发生换月 —— 决定该数值是否为"名义值"
```
**前 6 项缺任一 → 不可入库；排名类记录再缺 `pct_basis`/`rolled_over` → 不可进入 rank20。**

### 4.2 核心表

```sql
-- 品种字典
variety(code PK, name, exchange, sector, leader_flag, active)

-- 合约字典
contract(code PK, variety_code, exchange, delivery_month, listed_date, expired_date)

-- 日行情（官方真值，唯一权威）
daily_quote(trade_date, contract, variety_code, exchange,
            open, high, low, close, prev_settle, settle,
            volume, open_interest, oi_change, turnover,
            source, fetch_time, PRIMARY KEY(trade_date, contract))

-- 主力序列（文华规则：双料最大 + 维持 + 退化让位）
main_series(trade_date, variety_code, main_contract,
            vol_rank1_contract, oi_rank1_contract, is_dual_max BOOL,
            switch_reason,          -- dual_max | hold | degraded_volmax | cold_start
            source, fetch_time,
            PRIMARY KEY(trade_date, variety_code))

-- 涨跌幅（两种口径 × 当日/20日，全部落库便于对账与切换）
pct_series(trade_date, variety_code, main_contract,
           pct_1d_settle,        -- (收盘-昨结)/昨结
           pct_1d_close,         -- (收盘-昨收)/昨收
           pct_1d_settle2,       -- (今结-昨结)/昨结  = 官方"涨跌2"
           pct_20d_continuous,   -- 主连口径
           pct_20d_same,         -- 同合约口径
           ref_date_20d, ref_close_20d, ref_settle_20d,
           rolled_over BOOL,     -- 20日窗口内是否换月
           source, fetch_time,
           PRIMARY KEY(trade_date, variety_code))

-- 日 K 线（D3：rank20 涉及品种）
daily_kline(trade_date, contract, variety_code,
            open, high, low, close, settle, prev_settle,
            volume, open_interest, oi_change, turnover,
            source, fetch_time, PRIMARY KEY(trade_date, contract))

-- 主连 K 线（未复权=文华口径；复权=本项目增值字段）
continuous_kline(trade_date, variety_code, adjusted BOOL,
                 open, high, low, close, volume, open_interest, settle,
                 source, fetch_time, PRIMARY KEY(trade_date, variety_code, adjusted))

-- 换月事件
rollover_event(date, variety_code, from_contract, to_contract,
               reason, old_vol, new_vol, old_oi, new_oi, created_at)

-- rank20 快照（定稿，D1+D2 的交付载体）
rank20(trade_date, direction,          -- gain | loss
       rank_no, variety_code, name, sector,
       main_contract,
       pct_20d, pct_1d, close, settle, prev_settle,
       volume, turnover, open_interest, oi_change,
       rolled_over BOOL,
       mode,                           -- reconcile(对齐文华) | analysis(加流动性阈值)
       source, fetch_time,
       PRIMARY KEY(trade_date, direction, rank_no, mode))

-- 持仓排名（前20会员，D4 可选增强）
member_position(trade_date, contract, variety_code, rank_no,
                long_oi, long_chg, short_oi, short_chg,
                participant_abbr, source, fetch_time,
                PRIMARY KEY(trade_date, contract, rank_no))

-- 仓单（D4 可选增强）
warehouse_receipt(trade_date, variety_code, wh_abbr,
                  wbill_qty, last_wbill_qty, diff, source, fetch_time,
                  PRIMARY KEY(trade_date, variety_code, wh_abbr))

-- 分析产出（D4，服务于 rank20 品种）
causal_logic(id, created_date, variety_code, direction, driver, evidence_json,
             confirm_date, invalidate_json, status, evidence_urls, model, created_at)

-- 采集运行日志
fetch_run(id, trade_date, source, started_at, finished_at, status,
          rows_written, error, http_status)
```

### 4.3 存储选型

- **SQLite**（WAL 模式）单文件，零运维、易备份、局域网直读；数据量估算：666 合约 × 250 交易日/年 × ~120B ≈ 20MB/年，十年也不到 300MB。
- 若后续要做跨品种因子回测再迁 **DuckDB**（列存、直接读 SQLite/Parquet）。
- **不引入 PostgreSQL/ClickHouse**：本地部署单人使用，属于过度设计。

## 5. 采集层设计

### 5.1 调度（对齐"每日同步"）

| 时点 | 任务 | 说明 |
| --- | --- | --- |
| 每次启动 | 补齐缺失交易日 | 幂等回补，解决关机漏采 |
| 08:45 | 盘前准备 | 刷新合约字典、交易日历 |
| 15:30 | 抓东财/新浪快照 | 得到 `intraday` 快照（供盯盘，非定稿） |
| **16:40** | **抓官方日报（主任务）** | SHFE/CZCE/GFEX/CFFEX 日行情 → `daily_quote` / `daily_kline` |
| 16:45 | 抓持仓排名 | SHFE `pm*.dat` → `member_position`（D4 可选） |
| 16:50 | 计算流水线 | 主力状态机 → 涨跌幅（当日+20日）→ **rank20** → 校验 |
| 17:00 | 触发模型分析 | 针对 rank20 品种生成硬逻辑（`02` §6 的 JSON 结构） |
| 02:40 | 夜盘后快照 | 更新 `intraday`，一般不需要 |

- 若官方日报尚未发布（CZCE 偏晚），用**退避重试**：每 10 分钟重试至 20:00，并记 `fetch_run.status='pending_release'`。
- **幂等**：所有写入用 `INSERT ... ON CONFLICT DO UPDATE`，重跑不产生重复。

### 5.2 抓取器规范

```js
// 统一 HTTP 客户端要点
1. 后端：Node https/http（禁止 curl / HttpClient）
2. 重试：3 次指数退避（1s/4s/16s），仅对 5xx/超时重试
3. 限频：同域 ≥ 500ms 间隔；GFEX 遵守其限流
4. 必需头：
   - 通用：User-Agent（浏览器串）
   - GFEX：Origin + Referer + X-Requested-With + Accept  ← 否则 403
   - 新浪：Referer: https://finance.sina.com.cn
5. 编码：CFFEX/CZCE 为 GBK，需 iconv 解码；其余 UTF-8
6. 落盘：原始响应先存 raw/ 目录（便于事后复核与格式变更排查）
7. 记录：每次请求写 fetch_run（含 http_status、字节数、耗时）
```

### 5.3 解析器清单

| 解析器 | 输入 | 输出 | 坑 |
| --- | --- | --- | --- |
| `shfe_daily` | `kx{date}.dat` JSON | `daily_quote` | 剔除 `DELIVERYMONTH="小计"` 行 |
| `shfe_position` | `pm{date}.dat` JSON | `member_position` | 只取 `RANK` 1..20，剔除 `999`(合计) 与 `-1/0`(类别) |
| `czce_daily` | `FutureDataDaily.txt` | `daily_quote` | 管道分隔；剔除 `小计`/`总计`；数字含千分位逗号；**GBK** |
| `gfex_daily` | `loadList` JSON | `daily_quote` | 字段名拼写是 `volumn`；末行 `variety="总计"`；日期格式 `20260915` |
| `cffex_daily` | CSV(GBK) | `daily_quote` | 含期权行（如 `HO2609-C-2500`），需按正则过滤出期货 |
| `em_clist` | JSON | `intraday_rank` | 单页上限 100，需翻 11 页；`f2/f3` 可能是字符串 `"-"` |
| `sina_daily` | JSONP | 校验源 | 需剥 JSONP 外壳；`p`=持仓量 |

### 5.4 解析强制规则（实测产出，全部来自 `05`）

| # | 规则 |
| --- | --- |
| R1 | **零成交合约必须过滤出榜单**：`成交量==0` 或 `今收盘==0` 时涨跌幅无意义（官方 `close=0` 会算出 −100%）。实测 CZCE 有 50 条此类合约（CY610/CY612/CY702…） |
| R2 | **但保留其结算价**：官方对零成交合约仍给结算价（板价），是有效信息，只是不参与排名 |
| R3 | **汇总行必须剔除**：SHFE `DELIVERYMONTH="小计"`、CZCE `小计`/`总计`、GFEX `variety="总计"` |
| R4 | **千分位清洗**：CZCE 文本形如 `7,607.00`，先 `replace(/,/g,'')` 再转数值 |
| R5 | **GBK 解码**：CZCE 与 CFFEX 为 GBK；数字与 `|`/`,` 是 ASCII，可容忍降级解析 |
| R6 | **字段拼写陷阱**：GFEX 成交量字段是 `volumn`（官方拼错），不是 `volume` |

## 6. 校准闭环（"确保数据相同可信"的落地机制）

这是 R2 的核心保障。**没有这一步，"一致"只是声明。**

### 6.1 三层校验

```
第一层 · 源内自洽（每次采集自动）
  - 我方算的涨跌幅 vs 交易所日报自带的"涨跌1" → 偏差 ≤ 0.01pct
  - close/high/low 关系合法：low ≤ open,close ≤ high
  - 持仓量与增减量的勾稽：oi(t) − oi(t−1) ≈ oi_change(t)
  - 成交量 > 0 但成交额为 0 → 标记异常

第二层 · 跨源对照（每次采集自动）
  - 官方 close vs 新浪 c vs 东财 close → |Δ|/close > 0.5% 告警
  - 官方 volume vs 新浪 v → |Δ|/volume > 5% 告警
  - 持仓量方向不一致 → 告警
  - 换月日单独放行阈值，但必须记 rollover 事件

第三层 · 与文华屏幕对账（人工/半自动，每周或口径变更后）
  - 用户在 wh6「主力合约报价」列表抄录：**20日涨跌幅 rank20**（品种 + 数值 + 顺序）、主力合约代码、结算价、持仓量
  - 系统提供「对账模式」：输入文华数值 → 输出逐项差异报告（见 6.2）
```

### 6.2 对账工具的输出形态

```
=== 口径对账报告 2026-09-16 ===

【A. 20日涨跌幅定标（最高优先）】
品种   主力       我方A(主连收)  我方B(主连结)  我方E(同合约)   文华值   命中候选
rb     rb2701        +2.88%        +3.12%         —           ?       ?
cu     cu2610        -0.83%        -0.97%         —           ?       ?
sc     sc2611       +43.40%       +45.32%         —           ?       ?
fu     fu2611        +9.22%       +11.00%         —           ?       ?
→ 定标结论：method_20d = ? , price_20d = ?

【B. rank20 成员与顺序对齐】
排名  我方品种   文华品种   一致   20日涨跌%  当日涨跌%  结算价  持仓量
 1      xx        xx        ✅      ...        ...       ✅      ✅
 ...
成员重合度：19/20  （差异项：xx，原因：流动性阈值过滤 / 口径不同）
顺序一致性：19/20
结论：口径一致；差异项已归因。
```

### 6.3 差异归因决策树

```
出现差异
 ├─ 是"20日涨跌幅不同"？ → 口径未定标 → 用换月品种比对 A/B/E 候选（§3.5.2）
 ├─ 是"主力合约不同"？   → 双料最大规则实现有误 or 跨日状态未持久化 → 检查 §3.2.2 状态机
 ├─ 是"当日涨跌幅不同"？ → 基准是昨结还是昨收 → 检查 §3.1 与 wh6 个性化设置
 ├─ 是"结算价不同"？     → 取到了盘中价而非结算价 → 检查源字段映射
 ├─ 是"榜单少一个成员"？ → 流动性阈值过滤掉了 → 切 `reconcile` 模式（不过滤）复跑确认
 ├─ 是"复权后价格不同"？ → 复权算法差异 → 检查 adjusted 标记与平移规则
 ├─ 是"跨换月品种偏差大"？→ 换月跳空 → 检查 rolled_over 标记与主连拼接
 └─ 是"字段根本没有"？   → 文华自有计算（均价/Scale/资金流）→ 明确标注不支持
```

## 7. 分析层（对接 `02` 文档）

- **输入**：`daily_rank`（定稿榜单）+ `daily_quote` + `member_position` + `warehouse_receipt` + 板块映射表。
- **流水线**：板块广度 → LeaderScore → 因果链归因 → 确认日判定 → 失效跟踪。
- **分析范围（硬约束）**：**只针对 D1 的 rank20 品种集合**做分析；不在榜内的品种不产出逻辑。
- **数据来源（不设限）**：本条链路**不要求**接入特定数据源、**不要求**字段完整度达标，允许灵活取材（资讯、产业数据、持仓排名、仓单、人工判断等任意可用来源）。
- **强制约束**（来自 `02`）：每条硬逻辑必须带 `driver / evidence / confirm_date / invalidate_if`，并给出证据来源；缺任一 → 不得上首页。
- **证据字段可获得性（建议性，非阻塞）**：持仓量 ✅、前20净持仓 ✅（SHFE 已通）、仓单 ⚠️（GFEX 有，SHFE 路径待找）、基差 ⚠️（需产业源，可选）。**缺失不构成 D4 的阻塞。**
