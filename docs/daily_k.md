## 1. 实测依据（数据源核查）

### 1.1 历史日K：新浪期货日K接口 —— 六所 + 月均价全覆盖

```

Headers: Referer: https://finance.sina.com.cn , 浏览器 UA
```

返回 JSONP，剥壳后是数组，**每根字段完整**：


### 1.3 备源：东方财富日K（部分可用）

```
GET https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=<市场码>.<代码>&klt=101&fqt=0&beg=0&end=20500101&lmt=130&fields1=f1,f2,f3&fields2=f51..f61
```
返回 `date,open,close,high,low,volume,turnover,amplitude,pct,change,turnoverRate`。

实测：SHFE（`113.`）166 根 ✅、CZCE（`115.`）315 根 ✅、DCE（`114.`）165 根 ✅；
**INE / GFEX / CFFEX 用 113/142/8 均返回 `data:null`（市场码不对，未进一步穷举）**。
→ 可作**部分备源**，不作主源。

### 1.4 实时行情的 OHLC（驱动"形成中的最后一根"）

现有实时源 `hq.sinajs.cn` 商品段（44 字段）实测含：

| 字段位 | 含义 |
| ---: | --- |
| `[1]` | 源时间戳 HHMMSS |
| **`[2]`** | **今开盘** |
| **`[3]`** | **最高价** |
| **`[4]`** | **最低价** |
| `[6]` | 最新价 |
| `[10]` | 昨结算 |
| `[13]` | 持仓量 |
| `[14]` | 成交量 |
| `[17]` | 源标注交易日 |

当前 `parseQuote()` 只取了 `[6]/[10]/[13]/[14]/[1]/[17]`，**`[2][3][4]` 未取**——补上即可驱动日K最后一根。

### 1.5 一个关键事实：日K的"最后一根"可能晚于已收盘交易日

实测（2026-09-20 周日）：

- 新浪日K最后一根 = `2026-09-18`（周五，最后一个**已收盘**交易日）
- 东财日K最后一根 = `2026-09-21`（周一）且已有 `O3096 H3105 L3094 C3104`

原因：**周五夜盘（21:00–周六 02:30）归属下一个交易日（周一）**。所以"当前正在形成的交易日"可能是**日历上的未来日期**，其日K正在夜盘里生长。

**这条直接决定实现方式**：不能只依赖历史接口的最后一根，必须**由实时行情自己维护形成中的那根**（`o/h/l/c/v/oi` 全部可从实时字段得到）。

## 2. 实现方案

### 2.1 三层数据合成（核心设计）

```
              ┌─────────────────────────────────────────────┐
 历史基底 ────▶│ 新浪日K（~165-224 根 OHLC+量+持仓+结算）      │  每天 1 次，82 请求 ≈3s
              └──────────────────┬──────────────────────────┘
                                 │  按日期合并，**官方优先**
              ┌──────────────────▼──────────────────────────┐
 官方校正 ────▶│ 六所官方日报（最近 32 个交易日，权威真值）    │  已有（每日 09:00 抓取）
              └──────────────────┬──────────────────────────┘
                                 │
              ┌──────────────────▼──────────────────────────┐
 实时形成 ────▶│ 实时行情 o/h/l/c/v/oi 驱动"最后一根"         │  盘中随 snapshot 更新
              └─────────────────────────────────────────────┘
```

**合并规则（按 `d` 日期）**

| 情况 | 取值 |
| --- | --- |
| 该日**在官方窗口内** | **用官方 OHLC**（`src:"eod"`）——保证与 rank20 榜单同源、可自洽 |
| 该日只在历史基底里 | 用新浪值（`src:"sina"`） |
| 该日 = 实时 `tradeDay` 且官方尚未发布 | 用实时值（`src:"live"`，前端高亮） |
| CFFEX 的官方日 | 官方无收盘价 → `c := s` 并标 `src:"eod_settle_as_close"`，图上提示 |

> **为什么官方优先**：rank20 已经建立在官方日报上。若 K 线用第三方量价，会出现"图上最后一根的量/结算与榜单对不上"的可信度问题（这正是 `10` 文档 §3.2 要防的）。

### 2.3 存储布局

沿用"数据契约 + 文件"的做法（与 `base.json` 一致，零依赖、可直读、易备份）：

```
<workspace>/rank20/kline/
├─ index.json                 # 清单：{ updatedAt, tradeDate, contracts: {RB2701: {bars,first,last,src}} }
├─ RB2701.json                # 单合约全量（保留最近 250 根）
├─ MA2610.json
└─ …                          # 85 个（含 3 个月均价）
```

单合约文件结构：

```jsonc
{
  "schemaVersion": 1,
  "contract": "RB2701",
  "variety": "rb",
  "name": "螺纹钢",
  "updatedAt": "2026-09-20T07:00:00.000Z",
  "sources": ["eod", "sina", "live"],
  "bars": [
    { "d": "20260819", "o": 3123, "h": 3132, "l": 3089, "c": 3096, "s": 3104, "v": 884858, "oi": 1642367, "src": "eod" },
    { "d": "20260921", "o": 3096, "h": 3105, "l": 3094, "c": 3104, "s": 0,    "v": 224065, "oi": 6943917520, "src": "live" }
  ],
  "rollovers": [ { "d": "20260918", "from": "RB2610", "to": "RB2701" } ]
}
```

**不存 SQLite**：当前服务零三方依赖，SQLite 需要原生模块。JSON 单文件 85 个 × 250 根 ≈ 4 MB，读写都是毫秒级；后续要接 `04 §4.2` 的 `daily_kline` 表时，这份 JSON 就是它的导入源。

### 2.4 采集与更新时机

| 时机 | 动作 | 成本 |
| --- | --- | --- |
| 每日 09:00 日报任务成功后 | 拉 85 个合约历史（≈3s）→ 与官方窗口合并 → 落盘 | +3s |
| 服务启动时 | 读 `kline/index.json`；缺失则触发一次补建 | 一次 3s |
| 盘中每轮 `snapshot` | 用实时 `o/h/l/c/v/oi` 更新内存中"形成中的那根"；**每 30s 或收盘时**落盘一次 | 0 额外请求 |
| 主力换月（`base.json` 重载） | 新主力若无 K 线 → 立即补拉该合约 | 1 请求 |
| 收盘后（15:15 / 次日 02:45） | 用当日官方日报校正最后一根，落盘定稿 | 0 额外请求 |

**额外流量预算**：每天 85 个请求（≈1.8 MB）+ 盘中 0 新增请求。
远低于 `10` 文档 §4.3 的闸门（≤40,000 req/日）。

### 2.5 API 契约（替换当前 501）

```
GET /api/variety/:variety/kline?days=120&mode=contract
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `days` | 120 | 返回最近多少根（上限 250） |
| `mode` | `contract` | `contract` = 当前主力单合约（与 rank20 口径一致，**不拼接**）；`continuous` 预留 |

响应：

```jsonc

  "mode": "contract", "updatedAt": "2026-09-20T07:00:00.000Z",
  "sources": ["eod", "sina", "live"],
  "liveBarDate": "20260921",        // 正在形成的那根（前端高亮）
  "bars": [ { "d":"20260819","o":…,"h":…,"l":…,"c":…,"s":…,"v":…,"oi":…,"src":"eod" } ],
  "rollovers": [ { "d":"20260918","from":"RB2610","to":"RB2701" } ],
```

### 2.6 前端：点击品种 → 就地折叠展开 K 线（用户明确要求）

**交互定义**

| 操作 | 行为 |
| --- | --- |
| **单击榜单任意行** | 在该行**正下方插入/移除一行** `<tr class="klineRow"><td colspan="10">…</td></tr>`，**就地展开或折叠** K 线面板；同时该行加 `data-expanded="1"` 高亮 |
| 展开时的行高 | 固定 **320 px**（主图 200 + 量 60 + 持仓 60），**先占位再绘制**，避免加载后布局跳动 |
| 换一个品种 | 上一个自动折叠（同时最多展开 1 个，避免看不懂） |
| 再点同一行 | 折叠 |
| `Esc` | 折叠当前展开项 |
| 键盘 | `j`/`k` 移动选中，`Enter` 展开/折叠（与现有键盘方案一致） |
| 面板内「详情」按钮 | 打开右侧抽屉（概览 / 硬逻辑 / 溯源）——**与行内展开分工不冲突** |

> 现状：单击行是打开右侧抽屉。改为「单击行 = 就地展开K线」，把抽屉入口移到展开面板内的按钮——因为用户要的就是"点一下就折叠显示K线"，少一次跳转。

**图表内容（Canvas 2D 手绘，零依赖，不用图表库）**

```
┌──────────────────────────────────────────────────────────┐
│ 螺纹钢 RB2701   ●实时   [日K ▾] [详情]              [✕]  │
├──────────────────────────────────────────────────────────┤
│ 主图 200px：蜡烛 + MA5/MA10/MA20 + 基准日竖线 + 换月标记  │
│   最后一根（形成中）用呼吸高亮描边                         │
├──────────────────────────────────────────────────────────┤
│ 成交量 60px：与主图共享 x 轴，红涨绿跌                      │
├──────────────────────────────────────────────────────────┤
│ 持仓量 60px：折线                                        │
├──────────────────────────────────────────────────────────┤
│ 十字光标：显示 日期 O/H/L/C 涨跌幅 量 持仓（跟随鼠标气泡）  │
└──────────────────────────────────────────────────────────┘
```

**渲染要求**

| 项 | 规定 |
| --- | --- |
| 尺寸 | `devicePixelRatio` 适配（`canvas.width = cssW × dpr`），否则高分屏发虚 |
| 配色 | 复用 CSS 变量（`--up/--down`），支持"红涨绿跌/绿涨红跌"切换，且**蜡烛实体+影线**同时表达，不只靠颜色 |
| 懒加载 | **首屏不请求任何 K 线**；只在展开时才 `GET`，并缓存到内存（切换回同一品种不重复请求） |
| 实时更新 | 展开状态下，复用已有 SSE `snapshot` 的行情字段滚动更新最后一根；**不新建轮询、不新建长连接** |
| 重绘节流 | 与表格同一节流（800ms）；十字光标移动走 `requestAnimationFrame` |
| 空/错状态 | 无数据 → "暂无K线（该合约新上市或数据源未覆盖）"；加载中 → 骨架条 |
| 无障碍 | 面板带 `aria-expanded` / `aria-controls`；键盘可展开、可读关键数值（表格形式 fallback） |

**滚动更新最后一根的判定（关键）**

```
snapshot.tradeDate > bars[last].d  → 追加一根 forming bar（o=实时开, h/l/c=实时, src="live"）
snapshot.tradeDate == bars[last].d → 原地更新：h=max(h,实时高), l=min(l,实时低), c=实时最新, v/oi=实时
snapshot.tradeDate < bars[last].d  → 忽略（脏数据/跨源回退）
```

## 3. 验收标准（可测）

| # | 指标 | 阈值 |
| --- | --- | --- |
| K1 | 覆盖率 | K 线可达的合约 = **85/85**（含 3 个月均价） |
| K2 | 历史深度 | 每个合约 ≥ **120** 根（实测最少 81 根，月均价合约按实际给足并如实标注） |
| K3 | 官方窗口内一致性 | 最近 32 个交易日的 OHLC 与交易所官方日报**逐日全等**（偏差 0） |
| K4 | 实时最后一根 | 盘中展开时，最后一根的收盘价与榜单 `最新价` **同值**，延迟 ≤ 2s |
| K5 | 交易日切换 | 夜盘进入新交易日时，最后一根按新 `tradeDate` **追加**而非篡改前一根 |
| K6 | 折叠交互 | 单击展开 → 再点折叠；同时最多 1 个展开；`Esc` 可折叠；`Enter` 可展开 |
| K7 | 布局稳定 | 展开/折叠前后，表格其他行**不位移**（面板插入在行下方）；首屏零 K 线请求 |
| K8 | 零依赖 | 前端不引入任何图表库；`import` 仍只有相对路径与 `node:`/浏览器内建 |
| K9 | 性能 | 展开到首帧 ≤ 300 ms（缓存命中 ≤ 50 ms）；单合约 JSON ≤ 120 KB |
| K10 | 降级 | 新浪不可用时，仅用官方窗口出图（≤32 根）并在图上标注"仅官方日报口径" |

## 4. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 新浪日K为公开源、**无 SLA**，可能改字段/限流 | 历史基底不可用 | 官方日报为权威兜底（K10）；东财为部分备源；字段解析失败即拒绝该根而非猜 |
| 新浪 `v`（成交量）与官方口径可能不一致 | 图上量与榜单对不上 | **官方窗口内一律用官方值**（K3 验收项） |
| **CFFEX 官方无收盘价** | 金融品种蜡烛实体失真 | `c := s` 并标 `src:"eod_settle_as_close"`，图上角标提示"收盘以结算价代" |
| 周五夜盘归属下一交易日（日历上的"未来日期"） | 最后一根日期反直觉 | 明确按**行情带回来的交易日**建 bar；图上对 forming bar 标注"形成中" |
| 主力换月 | 图上出现合约跳变 | 按 R5 **单合约不拼接**；换月点在图上打标记；快速跳变处不连线（避免视觉骗线） |
| 月均价合约历史短（81 根） | 画不满 120 根 | 如实按实际根数绘制并标注；不补造数据 |
| 首次构建需 85 个请求 | 启动慢 3s | 异步后台建，不阻塞服务启动；缺失期间该品种显示"K线构建中" |
| Canvas 手绘工作量大 | 开发成本 | 分两步：先"蜡烛+量+十字光标"（MVP），再加 MA/持仓/缩放 |
