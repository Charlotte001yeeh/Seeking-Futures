# 07 · 为什么必须自己算：文华排名数据的可获取性结论

> 触发：用户提出"**你只需要得到文华财经的官方排名数据即可，不需要自己计算**"。
> 本文是对这一要求的**技术可行性核查结论**。结论先行：**文华的官方排名数据在外部不可获取**，因此"自己算"不是方案选择，而是**唯一可行路径**。

---

| 渠道 | 是否提供排名数据 |
| --- | --- |
| wh6 桌面免费客户端 | ❌ 不支持导出 |
| **随身行（手机端，用户实际入口）** | ❌ App 内渲染，**无 HTTP 接口**；与 wh6 同一套私有协议 |
| wh7 付费客户端 | ❌ 只能导出逐合约 K 线，**不是排名** |
| WT9 付费 API（3-6 万/年/交易所） | ❌ 只有 `GetKLineData` / `GetTickData`，**无排名接口，且不含当日** |
| 文华行情服务器 `wh6.wenhua.com.cn` / `app.wenhua.com.cn` | ❌ 私有二进制协议 + 账号鉴权，非 HTTP API |
| 逆向客户端 / APK | ⛔ **违反软件许可，本项目禁止** |

## 1. 直接把结论说清楚

| 问题 | 结论 |
| --- | --- |
| 文华有"官方排名数据"吗？ | **有**，就是客户端/App 里那个「报价综合排名」（主力合约涨幅、跌幅、成交量等排名） |
| 这个数据能对外获取吗？ | **不能**。既没有公开接口，也没有导出接口，付费 API 也不提供 |
| 那怎么才能拿到？ | **只有两条路**：① 人工从客户端/App 读；② 逆向客户端（禁止） |
| 所以我们该怎么做？ | **用官方交易所数据复现文华的口径**——这是唯一可自动化、可合规的路径 |

**"换月口径定标"要解释的就是**：复现时必须知道文华在处理"主力合约换月"时，取的是哪条价格序列。这个信息**只存在于文华的客户端算法里，外部无法查询**，只能通过**比对一个真实数值**反推出来。

---

## 2. 逐条核查：所有"官方渠道"都不提供排名数据

### 2.1 文华官网 / 客户端（【实测✅】可达，但无排名接口）

```
【实测✅】https://www.wenhua.com.cn/            status=200  38,449 bytes
【实测✅】https://www.wenhua.com.cn/guide/lssj.htm  status=200  33,334 bytes
【实测✅】DNS www.wenhua.com.cn     -> 58.205.209.132~139
【实测✅】DNS wh6.wenhua.com.cn     -> 121.194.1.22~29   （客户端连接用行情服务器）
【实测❌】DNS hq.wenhua.com.cn      -> 解析失败
【实测❌】DNS quote.wenhua.com.cn   -> 解析失败
```

- 官网可达，但**只有文档与下载页**，没有任何行情数据接口。
- `wh6.wenhua.com.cn` 是**客户端专用行情服务器**，走的是**私有二进制协议 + 账号鉴权**，不是 HTTP API。
- `ftpc1.wenhua.com.cn/files/guide/wh9/WHDataApi.rar` 返回 **403**（需登录/授权）。

### 2.2 文华官方「历史数据服务」API（付费，但仍不提供排名）

官方文档（<https://www.wenhua.com.cn/guide/lssj.htm>）列出的**全部接口只有三个**：

| 接口 | 返回 |
| --- | --- |
| `GetKLineData(df, code, beginTime, endTime, period)` | K 线：Time/Open/Close/High/Low/Volume/OpI/AVPrice/Scale |
| `GetKLineDataOfTheYear(...)` | 外盘年度 K 线 |
| `GetTickData(df, code, time)` | Tick：Price/Volume/Activity/五档买卖 |

**没有任何一个接口返回"主力合约报价列表"或"20 日涨跌幅排名"。**

补充约束（都是官方原话）：
- **"不包含当前交易日的数据"** —— 只面向回测。
- 费用：K 线 **30,000 元/年/账号/交易所**；tick+K 线 **60,000 元/年/账号/交易所**。
- 前置条件：**必须先用授权账号登录 WT9 通用版客户端**，API 通过本地端口 7800/7600 与客户端通信。

> 即"付费也不给排名"：这个 API 是**按合约取 K 线**的，不是取榜单的。而且它连当天的数据都没有。

### 2.3 wh6 免费版 / wh7 付费版的导出能力

| 版本 | 导出能力 |
| --- | --- |
| **wh6（免费）** | **不支持导出**（客服明确："需要使用 wh7 版本，wh7 是收费软件"） |
| wh7（付费） | 支持 "K线图右键 → 更多 → 导出数据"，导出**日线基础数据与逐笔明细** |

**关键**：wh7 导出的是**逐个合约的 K 线序列**，不是"排名列表"。而且导出的仍是**原始行情**，20 日涨跌幅排名是客户端**运行时算出来显示的**，没有落盘成可导出的表。

### 2.4 手机端「随身行」的核查（用户实际使用的入口）

用户查看文华官方排名的入口是**手机端「随身行」**（文华官方 App）。核查结果：

**产品确认**

| 项 | 内容 |
| --- | --- |
| 产品名 | **随身行**（文华随身行） |
| 官方站点 | `https://app.wenhua.com.cn/`（【实测✅】200） |
| 平台 | Android / iPhone / 鸿蒙 |
| 查看排名的路径 | **官方客服原话**："报价列表界面，主菜单 → **报价综合排名**，可以查看主力合约的涨幅，跌幅，成交量等排名" |
| 补充限制 | 官方另一条回复："报价列表数据量太大，**不支持点击抬头排序**" → 所以只能用「报价综合排名」这个固定入口 |

**可编程获取性核查**

```
【实测✅】DNS app.wenhua.com.cn  -> 121.194.1.23,25,27,28,29   （与 wh6 行情服务器同一批 IP）
【实测✅】DNS m.wenhua.com.cn    -> 223.5.179.219
【实测❌】DNS api./data./ssx.wenhua.com.cn  -> 解析失败（不存在）
【实测✅】m.wenhua.com.cn      -> 200，但只是静态宣传页（14KB HTML，jQuery 1.4.4 时代的老站）
【实测✅】m.wenhua.com.cn/index/updateurl -> 302 跳转到 .apk 下载
        → m-down.wenhua.com.cn/down_app/WenHuaManual7.7.10_436_201483.apk
```

**结论**：

1. `app.wenhua.com.cn` 解析到的是**与 wh6 相同的行情服务器集群**，说明 **App 与桌面端走同一套私有二进制行情协议**，而非 HTTP API。
2. 手机端的"报价综合排名"是 **App 内部的渲染结果**，**没有任何 Web/HTTP 入口**。
3. 唯一能程序化取到它的方式是**下载 APK 逆向其协议** —— 这属于逆向工程：违反软件许可、数据未获授权、且随版本升级随时失效。

> ⛔ **本项目禁止逆向。** 因此：**"直接用文华官方排名数据"这条路，在手机端同样不成立。**

### 2.5 结论

> **文华的"20 日涨跌幅 rank20"不是一个可以下载的数据集，而是客户端根据行情实时计算并渲染的界面结果。**
> 官方提供的所有对外能力（wh6/随身行客户端、WT9 付费 API、wh7 付费导出）**都不包含这个排名本身**，也没有任何 HTTP 接口暴露它。

## 3. 那"自己算"到底要解决什么——"换月口径"用大白话讲

### 3.1 问题从哪来

期货合约**会到期**。螺纹钢的主力合约现在是 `rb2701`，几个月后它到期，主力会换成更远的月份。文华的"主连"就是把不同时期的主力合约**首尾相接**连成一条长曲线。

**换月那天，新旧两个合约的价格不一样，接起来就有一个"台阶"（跳空）。**

### 3.2 为什么它会影响"20 日涨跌幅"

假设 `rb` 在 20 天窗口内换过一次月。那么"20 天前的价格"就有两种取法：

| 取法 | 20 天前那一格的价格 | 结果 |
| --- | --- | --- |
| **主连口径** | 当天主力合约（可能是**旧合约**）的价 | 首尾之间**跨过了那个台阶** → 数值含跳空 |
| **同合约口径** | **今天这个合约**（新合约）20 天前的价 | 全程同一个合约 → **不含跳空** |

**实测差距（2026-09-15，螺纹）**：

| 口径 | 20 日涨跌幅 |
| --- | --- |
| 主连口径（收盘） | **+2.88%** |
| 主连口径（结算） | +3.12% |
| 同合约口径 | 窗口内换过月，**无定义**（当时那个合约还没成为主力） |

这就是为什么"自己算"会算出跟文华不一样的值——**不是算错了，是不知道文华取了哪一种**。

### 3.3 为什么"20 天"和"昨天"不一样

- **昨天（当日涨跌幅）**：只有一种算法，`(今收盘 − 昨结算) / 昨结算`。**已经验证过，与交易所官方值偏差 0.0000pct**，没有任何歧义。
- **20 天**：要回答"20 天前"这个点时，主力合约**可能已经不是同一个了**，于是产生歧义。

所以歧义**只出现在跨换月的品种上**。实测这一批里，螺纹、铜、原油、燃油、镍、锡 6 个品种的 20 日窗口内换过月；沥青、铝、银、金没换过。**只有换过月的那几个，才能用来判断文华用的是哪种口径。**

### 3.4 "定标"要做的事，就一句话

> **从文华的屏幕上读一个数字，看我算的哪个候选等于它，就知道了文华的算法。**

这不是"算不算"的问题，而是**算法参数未知，需要一个观测值来确认**。确认之后，就可以用同一套算法对**全部品种、每一条历史**自动计算，不需要再人工读任何数据。

## 4. 四条可选路径（含代价）

| 路径 | 能拿到什么 | 自动化 | 合规 | 代价 |
| --- | --- | --- | --- | --- |
| **A. 复现口径**（当前方案） | 全部品种 × 全部历史的 20 日 rank20 | ✅ 完全自动 | ✅ 只用公开数据 | 需要**一次性**读 3-4 个数字确认口径 |
| **B. 人工读客户端** | 只有当天的 20 条榜单 | ❌ 每天人工抄 | ✅ | 每天 10 分钟，无法回溯历史，模型没有历史输入 |
| **C. 逆向 wh6 客户端** | 理论上全部 | ✅ | ❌ **违反软件许可 + 数据未授权** | **本项目禁止** |
| **D. 买 WT9 API** | K 线与 tick（**仍无排名、无当日**） | ✅ | ✅ | 3-6 万/年/交易所，**且解决不了排名问题** |

**A 是唯一同时满足"自动化 + 合规 + 覆盖全历史"的路径**，也正是你最初"本地部署 + 每日同步 + 模型分析"这个目标的必要前提。

## 5. 需要你做的（一次性，约 1 分钟）

**在你的手机「随身行」里**：报价列表界面 → 主菜单 → **报价综合排名**（文华官方指引的路径），按 **20 日涨跌幅** 排序，读出这几个品种的数值：

```
rb（螺纹钢）= ?      cu（沪铜）= ?
sc（原油）  = ?      fu（燃油）= ?
```

只要数字，不要截图。对上号我就把口径写死进配置，之后**全流程自动化，不再需要任何人工读数**。

> **只有换月品种是有效样本**：rb / cu / sc / fu / ni / sn 在近 20 日内换过主力；bu / al / ag / au 没换过，**无法区分口径**。
> 方便的话多读 `ni`（沪镍）与 `sn`（沪锡），交叉确认更可靠。

> 如果这 4 个数**一个都对不上**，说明文华用了第 6 种我没想到的口径（例如按**合约乘数加权**或**自定义换月日**），那我就换一组建模思路继续逼近——但无论如何，**都需要至少一个观测值**，这是信息论的硬限制，不是工程上的偷懒。

## 6. 对文档的修正说明

本文修正了此前"定标"一词造成的误解：它不是"让你参与计算"，而是"**用一个观测值确认一个未知参数**"。
一旦确认，本项目就是**纯自动化**的：官方交易所数据 → 复现算法 → 每日 rank20 → 模型分析 → 前端展示，无任何人工环节。
