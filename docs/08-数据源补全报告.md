## 3. 大商所 DCE：绕过注册是否可行 → **不可行**，但已找到合法替代源

### 3.1 站点被 WAF 全面拦截

```
【实测❌】http://www.dce.com.cn/                                        → 412
【实测❌】http://www.dce.com.cn/publicweb/quotesdata/dayQuotesCh.html  → 412
【实测❌】https://extportal.dce.com.cn/                                → ETIMEDOUT / EPROTO
```

换 UA、完整浏览器头、JSON POST、表单 POST、HTTP/1.1、**走系统代理（127.0.0.1:7890）**、**Chrome headless** —— **全部 412**。

### 3.2 WAF 类型判定：瑞数（Ruishu）动态保护，不是 IP 封禁

响应头是关键证据：

```
HTTP/1.1 412 Precondition Failed
Server: ******                                    ← 服务名被刻意隐藏
Set-Cookie: hNUS9DnJtejwS=qaPql...; Path=/;      ← 动态名 Cookie（每次不同）
```

- `412` + `Server` 被打码 + **动态名 Cookie** = 典型的**瑞数 VMP 动态安全**。
- 机制是**要求执行 JS 生成有效 Cookie 令牌**，而非按 IP 拒绝。
- **因此换 IP / 换代理 / 换 UA 都无效**（实测代理仍 412）。

**旁证**：AKShare 官方仓库有对应 issue —— *"大商所持仓排名接口返回 412 HTML，futures_dce_position_rank 报 BadZipFile"*（<https://github.com/akfamily/akshare/issues/6970>）。说明**上游库同样被拦**，不是本机环境问题。

### 3.3 唯一的免注册"绕过"= 逆向瑞数 JS → **否决**

技术上存在路径（Node 补环境执行瑞数 JS 生成 Cookie），但：
- 属于**对抗交易所安全机制**
- **随时失效**（瑞数定期更新）
- 与"不逆向客户端"的项目红线冲突

**结论：大商所官网数据，注册是唯一可持续的合法路径。**

### 3.5 ⚠️ 但主连序列不能用于 20 日公式（重要发现）

用新浪**主连**（`SC0`/`RB0`/`CU0`/`FU0`）计算 20 日涨跌幅，与文华读数比对：

| 品种 | 新浪主连算出 | 文华读数 | 偏差 |
| --- | --- | --- | --- |
| sc | 41.30% | 43.85% | **−2.56** ❌ |
| rb | 3.24% | 1.69% | **+1.55** ❌ |
| cu | 0.71% | 0.97% | −0.26 ❌ |
| fu | 18.11% | 18.11% | −0.005 ✅ |

而用**交易所官方单合约日报**（`sc2611`/`rb2701`/`cu2610`/`fu2611`）算，**4/4 精确命中**。

> **结论**：20 日公式**必须用单合约序列**，**禁止用主连**。主连在换月点拼接，20 日窗口一旦跨换月就会引入跳空误差。
> 新浪单合约接口（`I2601` 形式）支持这一点，因此新浪可替代 DCE。

### 3.6 大商所官方 API：**接入协议已完全打通，但账号尚未授权数据接口**

已用用户提供的凭证实测。**认证链路完全成功**，缺的是**接口级授权**。

#### 3.6.1 认证成功 ✅

```
POST /dceapi/cms/auth/accessToken
Header: apikey: <API_KEY>
Body:   {"secret": "<SECRET>"}
→ {"success":true,"code":200,"msg":"安全Token签发成功","data":{"tokenType":"Bearer","token":"eyJ...","expiresIn":28800}}
```

- Token 类型：**Bearer JWT**，有效期 **28800 秒（8 小时）**
- JWT payload：`{"aud":"internal-services","service_name":"<API_KEY>","iss":"api-auth-service","sub":"<API_KEY>","exp":...}`
  （说明书原样记下了真实 `service_name` 值；**已脱敏** —— 凭据不入库，见 `.env.example` 与 `docs/12`）

#### 3.6.2 数据请求所需的 Header（已确认）

```
Authorization: Bearer <token>
apikey:        <API_KEY>
tradeType:     1        ← 1=期货, 2=期权
lang:          zh
Content-Type:  application/json

```
[common/varietyList]   → {"code":401,"msg":"无权限访问该接口"}
[member/dailyRanking]  → {"code":401,"msg":"无权限访问该接口"}

**结论**：
- Token 签发成功，但该 `api_key` **未获得任何数据接口的访问授权**（401 而非 403/404，且路径被正确识别说明路径无误）。
- 这不是路径或参数问题，而是**账号权限问题**。

**需要用户在门户完成的操作**：

1. 登录大商所对外门户 → **数据服务 → API 服务**
2. 检查该 `api_key` 的**数据权限是否已申请/开通**
3. 按需申请：
   - **Market（日行情）** ← D1/D2/D3 必需
   - Member（会员成交排名）← D4 可选
   - Delivery（仓单）← D4 可选
4. 若门户有限流设置，注意其**频次限制**（本次实测：短时间内多次调用会触发 `超出访问频次，已停止访问60秒`）

| 优先级 | 用途 | 源 |

| **一档（真值）** | 行情/结算价/持仓量 | 交易所官方：SHFE、CZCE、INE、GFEX、CFFEX、**DCE（凭 token）** |
